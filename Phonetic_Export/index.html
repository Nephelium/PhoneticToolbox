1 程序概览与简介

1.1 关于 PhoneticToolbox

图 1-1：PhoneticToolbox 主功能面板

PhoneticToolbox 是一款基于 Python 和 PyQt6 框架自主研发的综合性语音分析与合成平台。PhoneticToolbox 在致敬并复刻经典 MATLAB 版 VoiceSauce 核心功能的基础上，为语音学研究者提供了一个现代化且易于扩展的图形化分析环境。相比于传统工具，它在易用性上实现了极大的跨越。

过去使用 VoiceSauce 时，研究者必须依赖庞大厚重的 MATLAB 环境才能运行脚本。考虑到大家在配置环境时经常遇到的苦恼，我们打造的 PhoneticToolbox 已经被整体封装为独立的 .exe 可执行程序。使用者无需具备编程基础，也不必去处理复杂的环境配置，只需在 Windows 系统下双击运行，便能直接投入到研究工作中，真正做到了即开即用。

在以往的语音学研究里，学者们常常要在不同的软件之间来回切换：提取参数用这一款，做合成换另一款，跑感知实验又要去寻找新的平台。这种工作流的割裂感不仅消耗科研精力，也很容易打断原本连贯的思路。PhoneticToolbox的设计初衷正是为了打破这层壁垒。它超越了单一参数提取器的局限，将声学分析、语音合成、生理信号处理以及感知实验深度整合为一站式工作站，让研究者可以把宝贵的精力全心全意地专注在学术思考本身上。

特别值得一提的是，PhoneticToolbox针对发声类型研究中的痛点进行了优化。比如在处理嘎裂这类复杂发声类型时，它集成了类似 REAPER 这样更具鲁棒性的基频检测算法。从全自动的数据提取到精细化的可视化修正，PhoneticToolbox为大家提供了一个完整的工作闭环，让日常繁琐的数据处理变得更加踏实和安心。

1.3 核心功能模块

PhoneticToolbox 的功能架构主要分为三大类：声学参数分析、语音编辑与合成、以及辅助工具。

声学参数分析核心

这是本软件最基础也最强大的部分，旨在对标VoiceSauce的功能。（除了共振峰提取时没有选择snake脚本）

参数估计

这是数据处理的起点。该模块能够批量处理.wav音频文件及.TextGrid标注文件，自动提取包括基频 (F0)、共振峰 (Formants)、以及复杂的声源参数（如 H1-H2, H1-A1, CPP, HNR 等）。系统集成了多种基频检测算法，包括经典的 Praat 算法以及专门针对嘎裂声优化的 REAPER 算法，确保了在复杂语音环境下的鲁棒性。

参数显示

提供交互式的可视化界面。用户可以加载计算好的数据文件，查看各类声学参数的轨迹及标注。

EGG 信号分析

专为生理语音学打造。支持双声道 EGG 信号的自动分离、归一化及逆滤波；能够精确检测声门速度商(SQ) 和闭合商(CQ)，并在语谱图上同步显示声门闭合/开放时刻（GCI/GOI），直观揭示声带振动机制。

语音操作与合成

这一板块为语音感知实验提供了极高自由度的材料制作能力。

可视化语音合成

内置了基于 Klatt 模型的串联/并联共振峰合成器。这是一个高度可视化的合成实验室，用户可以直观地调节 F0、共振峰频率、带宽以及声源类型（如耳语、气声、嘎裂等），实时生成符合特定声学特征的语音样本。

变速变调

基于 Parselmouth (Praat) 的 PSOLA 与重采样算法，提供高质量的语音操纵功能。支持对原始语音的基频曲线进行手绘式修改，或进行时长伸缩。您可以对原始语音的基频曲线和时长进行精细调节，可用于制作声调感知实验的刺激材料。

感知实验

一个轻量级、基于 Web 技术（HTML5/JS）的实验系统。支持快速构建 AX 区分、ABX 区分、情感识别等经典实验范式，生成的实验可直接在本地运行并自动记录反应时。

数据管理与辅助

手动数据 (Manual Data)

可直接查看保存的参数。

设置

允许用户自定义分析参数的默认值（如窗长、步长、基频范围等），以适应不同性别或语种的语音材料。

设置界面

此区域包含了影响语音参数提取（如基频、共振峰、能量、频谱倾斜等）的核心参数。

图 7-1：设置界面

能量参数

能量阈值（比例）

  • 含义：用于判断语音片段是“有声”还是“无声/静音”的相对能量阈值。
  • 作用：系统会计算整段音频的最大能量（Max Energy）。如果某帧的能量低于 Max Energy × 能量阈值，该帧将被视为静音段，不进行某些参数的计算或将其标记为无效。
  • 推荐值：默认0.03(即3%)。如果录音背景噪音较大，可适当调高此值；如果语音较弱，可适当调低。

能量窗口（毫秒）

  • 含义：计算短时能量时所使用的窗口长度。
  • 作用：决定了能量计算的时间分辨率和平滑程度。
  • 推荐值：默认40ms。

帧与窗口参数

帧移（毫秒）

  • 含义：两个相邻分析帧之间的时间间隔（步长）。
  • 作用：决定了输出数据的时间密度。较小的值（如1ms）提供更高的时间分辨率，但计算量增大，数据量增加。较大的值（如10ms）计算更快，但可能丢失快速变化的细节。

窗宽（毫秒）

  • 含义：对每一帧进行频域分析（如计算共振峰）时所截取的信号长度。
  • 作用：宽窗：频率分辨率高，时间分辨率低（适合观察谐波结构）。窄窗：时间分辨率高，频率分辨率低（适合观察共振峰）。
  • 推荐值：默认25ms (对于一般语音分析是通用的选择)。

平滑点数

  • 含义：对输出的参数轨迹进行移动平均平滑的窗口大小（点数）。
  • 作用：0表示不进行平滑。大于0的值会使曲线更平滑，去除微小的抖动，但可能掩盖真实的快速变化。

周期估算参数

本软件在计算不同声学参数时，会根据基频（F0）动态调整分析窗口的长度（即截取多少个基音周期）。这两个参数的设置与VoiceSauce相同。

谐波估计周期数

  • 含义：在计算频谱谐波幅值（如 H1, H2, H4, A1, A2, A3, H2k, H5k）时，截取的基音周期数量。
  • 作用：谐波分析需要较高的频率分辨率，因此通常需要包含多个完整的基音周期。
  • 推荐值：默认3。过少可能会导致频谱泄露，过多会降低时间分辨率。

能量/CPP/HNR 周期数

  • 含义：在计算能量 (Energy)、倒谱峰值突出度 (CPP) 和 谐波噪声比 (HNR) 时，截取的基音周期数量。
  • 作用：这些参数对窗口长度的敏感度与谐波不同，因此独立设置。
  • 推荐值：默认5。

输出过滤

  • 含义：对语音进行短时过零率检测，判断请浊音。
  • 作用：若勾选，计算参数时，只计算浊音的参数。默认勾选。

本软件使用 REAPER 算法（Google 开发的鲁棒性基频追踪算法）作为主要的基频提取手段之一。

最低基频

  • 含义：F0 搜索范围的下限。
  • 作用：防止将低频噪音误判为基频，或防止产生过低的倍频程错误（Octave Error）。
  • 推荐值：男性语音通常可设为50-70Hz，女性可稍高。默认40Hz。若主要研究嘎裂相关发声类型，可设置为20。

最高基频

  • 含义：F0 搜索范围的上限。
  • 作用：防止将高频共振峰或噪音误判为基频。
  • 推荐值：默认500Hz。对于儿童或高音歌唱，可能需要调高。若主要研究假声相关发声类型，可设置为1000。

hilbert

  • 含义：是否在分析前对信号应用希尔伯特变换。
  • 作用：勾选：推荐用于经过非线性相位失真的信号（如录音室后期处理过的音频）或近讲麦克风录音。它可以改善残差信号的峰值特性。不勾选：适用于原始波形保持较好的信号。
  • 默认：勾选。

no-highpass

  • 含义：是否禁用 REAPER 内部默认的高通滤波器。
  • 作用：勾选：禁用高通滤波。REAPER 默认会滤除低频分量以去除直流偏置和低频隆隆声。如果你的信号已经是清洗过的，或者你需要保留极低频成分，可以勾选此项。不勾选：启用高通滤波（REAPER 官方默认行为）。
  • 默认：不勾选。

6 感知实验

6.1 实验设计与配置

感知实验平台是一个基于 Web 技术构建的轻量级、无需后端的听觉感知实验平台。它不仅支持基础的单刺激听辨，还全新集成了 AX、ABX、AXB 等经典的语音区分任务范式。平台支持通过可视化界面进行实验设计、音频刺激呈现、问卷调查以及反应时数据记录，非常适合开展语音感知、听辨实验等心理学与语言学研究。

实验范式选择

启动平台后，首先进入 “范式选择” 界面。这是构建实验的第一步，决定了后续的文件管理结构与播放逻辑。

支持的范式：

  • 单刺激 (X)：传统的听辨任务。播放一个音频，要求被试根据直觉做出判断（如：辨认声调、元音类别）。
  • 区分任务 (AX)：播放序列 A -> X。被试需判断 X 是否与 A 相同，或判断 X 的某种属性。
  • 区分任务 (ABX)：经典的范畴感知范式。播放序列 A -> B -> X。被试需判断 X 听起来更像 A 还是更像 B。
  • 区分任务 (AXB)：播放序列 A -> X -> B。被试需判断中间的 X 更像 A 还是更像 B。

图 6-1：实验范式选择界面

在 “音频数据库” 标签页中，界面布局会根据你选择的范式自动调整。

分组管理：

  • X 范式：仅显示一个上传区域（刺激列表 X）。
  • AX 范式：显示两个上传区域，分别用于上传 参照刺激 (Stimulus A) 和 目标刺激 (Stimulus X)。
  • ABX/AXB 范式：显示三个上传区域，分别对应 Stimulus A、Stimulus B 和 Stimulus X。

7.1 唇形录制

本界面是专为语音学研究设计的唇形特征自动提取工具。它基于 MediaPipe Face Mesh 深度学习框架，能够以高帧率实时捕捉面部 468 个关键点，并针对语音发音过程中的唇部运动进行量化分析。

特征参数定义与计算方法

本章节详细定义了软件输出的各项声学与生理特征参数。所有“归一化”参数均已消除距离影响。

参考基准

为了实现归一化，系统首先定位面部轮廓的极点：

  • Face Width (面宽度)：左脸颊边缘点 (Idx：234) 与右脸颊边缘点 (Idx：454) 之间的欧几里得距离。
  • Face Height (面高度)：前额顶点 (Idx：10) 与下颚底点 (Idx：152) 之间的欧几里得距离。

图 7-3：面部特征点

核心唇形参数

1. Normalized Lip Height (归一化唇高度)

  • 定义：上唇最高点与下唇最低点在垂直方向上的投影距离，与面部高度的比值。
  • 计算公式：$H_{norm} = \frac{Lip_{top} - Lip_{bottom}}{Face_{height}}$
  • 语言学意义：衡量元音发音时的开口大小（如 /a/ vs /i/）。

2. Normalized Outer Width (归一化外唇宽)

  • 定义：左唇角 (Idx：61) 与右唇角 (Idx：291) 之间的水平距离，与面部宽度的比值。
  • 计算公式：$W_{outer\_norm} = \frac{Lip_{right} - Lip_{left}}{Face_{width}}$
  • 语言学意义：衡量展唇与圆唇程度（如 /i/ 的展唇度）。

3. Normalized Inner Width (归一化内唇宽度)

  • 定义：内唇廓的水平宽度与面部宽度的比值。
  • 应用场景：在唇音（如 /m/, /b/）分析中，该值应趋近于 0，但外唇宽仍存在数值。（但是实际上由于测量误差，一些圆唇元音如/u//y/等也常常出现内唇宽度为0的现象，因此实际写论文时并未采用这一参数）

4. Lip Openness (垂直开口度)

  • 定义：上唇下缘 (Idx：13) 与下唇上缘 (Idx：14) 之间的垂直距离，并进行归一化。
  • 注意：若双唇紧闭挤压，该值可能出现微小的负值，属于正常物理现象。

5. Lip Area Ratio (唇部面积比)

  • 定义：外唇轮廓围成的多边形面积减去内唇轮廓围成的多边形面积（即嘴唇本身的肌肉面积 + 口腔开口面积），再除以面部轮廓的总面积。

6. Circularity (唇圆度)

  • 定义：描述唇形接近完美圆形的程度。
  • 计算公式：$C = \frac{4\pi \times Area}{Perimeter^2}$
  • 数值越接近 1.0，表示唇形越圆（如发圆唇元音 /u/, /o/）。
  • 数值越接近 0.0，表示唇形越扁长（如发展唇元音 /i/ 或闭嘴时）。

  • 如果生成的图表中出现断点或 NaN 值，说明在该时间段内未检测到人脸。请检查录制时的视频画面。

8.3 常见问题与注意事项

Q1: 运行日志中出现 soundfile 或 dll 加载错误？

  • 本工具为便携版，已内置运行所需的动态链接库。如果出现此类错误，通常是因为系统环境缺失某些基础 VC++ 运行库。请确保系统已安装最新的 Visual C++ Redistributable。

Q2: 对齐生成的 TextGrid 里面为什么是空的，或者缺少部分单词？

  • 这通常是因为音频对应的文本内容（.lab 文件）中包含了发音字典（.dict）里不存在的词汇。
  • MFA 只能对字典里已有的发音进行对齐。请检查您的文本标注，确保所有汉字或拼音都在字典文件中能找到对应的条目。

Q3: 音频格式有什么特殊要求吗？

  • 虽然工具底层支持多种音频格式，但为了获得最佳兼容性和对齐精度，强烈建议使用标准的 WAV 格式（采样率 16000Hz 或 44100Hz，16-bit，单声道 PCM 编码）。
  • 尽量避免使用 MP3 等有损压缩格式，因为它们在解码时可能会产生微小的时间偏移，影响对齐边界的准确性。

Q4: 为什么对齐的边界不够精准，还需要人工修改？

  • 本工具使用的是通用预训练声学模型，它涵盖了广泛的发音特征，但无法针对每一个特定说话人的发音习惯进行完美适配。
  • 自动对齐的主要目的是提供一个粗略的基准，大幅减少从零开始标注的工作量。所有自动生成的边界都应当被视为“参考建议”，在进行严谨的语音学分析前，务必使用 Praat 进行人工校对。

Q5: 能否在文本标注中混合使用中文和英文？

  • 这取决于您所加载的发音字典。

重建算法与音频合成

音频重建过程采用以下核心算法逻辑：

灰度-分贝映射：

将灰度图像的像素值（0-255）映射为对数幅度谱（dB）。颜色越深（灰度值接近 0）代表能量越强（0 dB）；颜色越浅（灰度值接近 255）代表能量越弱（-30 dB）。随后将对数幅度谱转换为线性幅度谱。

Griffin-Lim 相位恢复：

由于普通语谱图仅包含幅度信息而丢失了相位信息，系统使用 Griffin-Lim 算法进行迭代估计。

  • 迭代次数：默认为 32 次，以在计算速度与相位一致性之间取得平衡。
  • 窗函数：使用 Hann 窗，窗长自适应调整（默认 128 点）。

重采样处理：

系统首先在计算出的原生采样率下合成音频，随后通过线性插值算法自动将音频重采样至通用的 44100 Hz，以确保在不同设备上的兼容性。
