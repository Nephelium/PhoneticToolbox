# MFA 自动标注 · M11

本目录把已转写 WAV 接入 Montreal Forced Aligner，负责资源选择、语料配对、任务状态、日志和结果保存。详细用户流程见[可编辑手册章节](../../../../manual/chapters/m11.json)，补充平台说明见[M11 文档](../../../../docs/manual/mfa.md)。模块名称和持久 ID 见[模块注册表](../../app/registry.ts)。

## 当前行为

- 桌面上方声学模型、发音词典下拉框直接打开原生文件导入。新资源待检查时暂停提交，检查通过后自动登记、应用并记忆；取消待检查选择恢复当前已应用组合。
- 下方组件管理只负责已有环境或可信离线 ZIP/清单，不重复放置模型和词典导入。检查使用固定 MFA 3.3.8 / Windows x86_64 和公开 `a`、`啊` 或 `a1` 对齐探针。
- [运行时登记](../../../../backend/src/ptb_worker/mfa/runtime.py)合并随应用提供的只读内置资源与用户可写登记。内置清单路径受限制，用户导入保留在稳定组件目录。可重定位运行时的隔离公开探针已运行，新的便携成品整包验收仍待完成。
- 当前 Kaldi/GMM-HMM 流程使用 CPU，没有 GPU 设备开关。资源摘要检查、词典音素兼容性和转写 OOV 分别处理。
- 桌面目录递归读取，文件入口只处理手选文件。自动来源要求唯一同名转写；显式 LAB/TXT/TextGrid 允许其他格式共存，不缺省回退。改变来源后必须重新读取。
- 唯一非空 `words` 层可转为整段转写重新对齐，旧 words 时间不约束新对齐，`phones` 不作词转写。独立转写层仍按 MFA 原生解析处理。
- 历史任务可刷新或取消。当前页面无一键重试按钮，失败后修正并重新读入资源/语料，再建立新任务。完整成果逐文件下载或在独立 MFA 子目录保存，不覆盖原 TextGrid。

## 输入、默认值与输出

| 对象 | 规则 |
| --- | --- |
| 语料 | WAV 与同目录、同基本名 LAB、TXT 或 TextGrid，接受单/双声道 |
| 输入上限 | 最多 100 WAV，每份 120 秒，提交资产合计 64,000,000 B，相对 WAV 路径 UTF-8 长度最多 110 B |
| 目录上限 | 扫描目录最多 10,000 条目，单份转写非空且最多 2,000,000 B |
| 模型与词典 | 已登记组合，或桌面实际检查的新模型 ZIP 和兼容词典。`mandarin.zip` 配指定 `mandarin_pinyin_tab.dict`；不要与 `mandarin_mfa.zip` 混配 |
| 搜索参数 | 新草稿 Beam 100 / Retry beam 400，旧明确保存值保留。整数范围为1–10000 / 1–40000，实际归一化规则见[state.ts](state.ts) |
| 执行预算 | 对齐子进程180秒，任务及库函数缓存共同临时空间软预算512,000,000 B。输入上限不保证成功 |
| 输出 | `001_基本名.TextGrid` 等按输入序号区分同名文件，及 `m11-provenance.json` |
| 溯源 | 输入资产及摘要、运行环境/模型/词典身份、实际参数、时间/标签、CPU执行信息、阶段耗时与TextGrid转写适配 |
| 日志 | 页面有界显示脱敏阶段和最后256 KiB MFA日志，完整本机诊断与失败部分输出保留 |
| 草稿 | 保存参数、运行环境ID、模型组合ID和转写来源；不保存待提交文件授权、输出目录或网页未登记词典 |

## 正常与失败流程

1. 选择已检查环境及模型/词典。已有登记组合可直接使用，新导入资源先检查并应用。
2. 指定转写来源并读入成对文件，核对整个语料清单、词典词条和模型音素兼容性。
3. 核对实际参数后开始对齐，查看阶段、任务记录及脱敏日志。进度不估算剩余时间。
4. 成功后保存所有 TextGrid 与溯源 JSON，将原 WAV 一起送入 M12/Praat 人工复核。
5. OOV 时先查具体词与转写；音素不兼容时恢复兼容组合。改变源文件后重新读取，再提交新任务。取消、超时或部分结果不等于完整成功。

## 验证入口与边界

开发入口：[Start-M11-Workbench.ps1](../../../../scripts/Start-M11-Workbench.ps1)，可指定既有 `-ComponentRoot`。前端修改按范围使用 `npm --prefix frontend run typecheck`、`npm --prefix frontend run test -- --run`、`npm --prefix frontend run build`。手册检查从根目录使用项目已有 Python 执行 `scripts/manual/validate.py --project manual --strict`。

[R2 报告](../../../../docs/testing/2026-10-05-m11-r2-report.md)记录顶部原生导入、兼容性拒绝、a1探针、实际任务保存及指定本机 EXE 流程。[R1 报告](../../../../docs/testing/2026-10-04-m11-r1-report.md)记录共存来源、CPU速度、缓存隔离和结果一致性。定向入口包括[资源 Qt 检查](../../../../scripts/verify_m11_r2_qt.py)、[运行环境检查](../../../../scripts/verify_m11_runtime.py)和[内置登记测试](../../../../backend/tests/test_m11_bundled_registry.py)。文档修改只执行说明书结构/引用与本地链接检查，不运行科研任务。

已有成品记录依赖指定本机环境。新增只读内置资源合并与隔离探针不等于新的便携成品已验收。远程执行桥、Linux/macOS GUI、新电脑完整安装和自然语料边界准确率均不能由本机公开小任务外推。网页使用管理员资源，当前未准入执行任务显示等待节点，仍遵循账号文件额度与保留政策。
