# P01 · 桌面宿主与音频视图原型

状态：verified（Windows 原型与来源风险评审）。2026-09-09 用户完成试用并反馈无问题，同意继续 P02。技术与人工证据见 P01 报告；历史来源许可和其他平台原生/设备限制依 ADR-013 继续保留，不等于发行完成。

## 范围与实现

- 验收环境为 `.venv/p01-standalone`，基于项目内独立 CPython 3.11.14。最初 conda 派生的 `.venv/p01-pyqt6` 暴露 ICU DLL 冲突，保留为失败证据，不用于构建。前端依赖仅安装到 `frontend/experiments/audio-viewport/node_modules`，不修改原 conda 环境。
- 首先验证 PyQt6 + Qt WebEngine。Vue/TypeScript/Vite 仅用于构建试验页面；运行时加载包内静态资源，无 Vite 开发服务器、无云端依赖。
- P01 只验证单页宿主能力，采用只读自定义 URL scheme 加载包内资源，禁止网络与任意本地文件跳转；不提前实现 P02 的统一本地 API。正式服务鉴权仍按总架构执行。
- 原始 WAV 采样率、声道和整数采样区间 `[start,end)` 为事实来源。显示降采样不修改原数组；试听按原始采样区间复制 AudioBuffer，由声卡自行做输出采样率转换。
- 支持 PCM 16/24/32 位和 IEEE float32 WAV 的有限探针格式；不支持的格式明确报错。原型不代表 v3 最终格式覆盖。
- 初始为空态。通过显式按钮载入可复现的双轨合成音，或只读打开自己的 WAV；不自动播放、不生成虚构分析结果。
- U2 主题、中文/IPA、双轨波形、采样选区、缩放、播放/暂停/停止与错误状态用于交互验收；全部业务模块仍未迁移。

## 工作顺序与验收

1. 保存 v2 Git HEAD/index/status、源码清单和 conda 包元数据的只读摘要；核对既有暂存区，记录历史原文的空白告警。
2. 先写 WAV/选区边界测试，再实现最小页面；运行 `npm.cmd --prefix frontend/experiments/audio-viewport run test`、`run typecheck`、`run build`。
3. 建立 Qt 宿主、资源限制、设备枚举与自动探针；运行 `.venv/p01-standalone/Scripts/python.exe -X utf8 -m pytest -c desktop/experiments/pytest.ini desktop/experiments/tests -q`。探针配置与 v2 的 coverage/测试发现范围分离。
4. 运行源码宿主自测，检查实际 WebEngine、中文/IPA、原始采样精度、主题/窗口尺寸、WebAudio 状态及截图。音频系统回环仅在显式音频验证模式中使用；不保存系统混音原始音频，不采集麦克风。
5. 使用隔离环境的 `python -m PyInstaller` 构建单文件探针；验证非项目工作目录、Unicode 路径、双实例及退出后本应用子进程回收。
6. 检查 VTL 2.4 本地源包/Windows DLL、REAPER 可执行文件与可重建来源；整理 Qt/PySide6/Tauri/Electron 的证据与代价。仅构建/运行过的方案标实测，未构建平台和许可缺口明确记录。
7. 汇总到 `docs/testing/p01-host-probe-report.md`，完整本地证据写入忽略的 `output/validation/p01/`。更新 ADR、来源登记和任务状态；达到退出条件后才标 verified。

## 状态边界

P01 包是本地技术原型，不是 v3 发布版本。Mac/Linux 原生设备、Windows 干净账户、签名、全部传递许可与科学等价性分别留待后续阶段。若单文件、设备或来源审查存在阻断，明确保留 P01 未通过门槛，不推进全面 UI 移植。
