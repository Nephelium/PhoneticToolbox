# P15-STAGING Implementation Plan

**Goal:** 完成可审阅部署准备和独立测试；实际目标授权后再验 HTTPS、政策和节点回退。

**Architecture:** 单机同 UID、同命名空间的 API/worker/清理器，复用现有 PostgreSQL、Storage、任务协议和 P11 受限执行。反向代理只开放同源 HTTPS。A/B/C 实现归原负责人，本任务不修改政策、调度或客户端协议。

**Tech Stack:** 现有 CPython 3.11.14、FastAPI/Uvicorn、PostgreSQL、systemd user manager、Nginx、现有 httpx/pytest。

状态：in_progress，部署未授权。用户本轮已授权准备与个人电脑 WSL 独立测试，无须重复确认这些工作。

## 1. 文件与归属

- 新增 `scripts/p15_staging/`：配置检查、服务器宿主、只读盘点、HTTPS 集成检查。只接现有公开构造器，不复制算法/政策。
- 新增 `deployment/p15-staging/`：公共配置、Nginx、systemd user unit、日志轮转模板。没有 apply、安装、DDL 或 DNS 自动化。
- 新增 `tests/staging/test_p15_staging.py`：错误配置、默认关闭、维护门、Host/Origin/CSRF、证据绑定和上传下载检查器自身回归。
- 新增 P15 专项决策、运行手册、报告、能力清单；共享 README/AGENTS/台账/矩阵待其他任务释放且整合稳定后更新。

## 2. 检查顺序

1. 只读核对根/目录规则、分支和差异。P07 接线及生成契约通过不等于目标库政策通过。
2. 只读核对 P11 完整 1800 秒原始报告、runtime/profile/hash，记录整合后源码漂移。
3. A/B/C 交付按路径/hash登记；未完成时只有服务器单独运行候选，远程保持关闭。
4. 逐模块核对实际 Linux capability、资源、字体/原生依赖、账号文件链路。M08/M14/ZIP 未关门前禁用。
5. WSL 只读盘点与无系统配置改动的独立测试。当前 NInfer 无 systemctl/systemd-run，完整计算节点保留 blocked。

## 3. 实现与验证

先写配置/HTTP 边界回归，再实现宿主适配及模板。配置默认 maintenance 且开放操作空集；上线前要求政策版本 2、同 UID 和真实 runtime receipt。模板不能填假的主机、域名或成功凭据。

Windows 命令：`$env:PYTHONPATH='backend/src;packages/phonetic_core/src;scripts/p15_staging'; .venv/v3-dev/Scripts/python.exe -m pytest -c tests/pytest.ini tests/staging/test_p15_staging.py -q`。

WSL 命令使用 `/home/ninfer/ptb-p11-20260926/venv/bin/python`，测试源码单独复制至用户目录的 P15 独立子目录；不覆盖原 P11 环境。另执行生成契约 `--check`、专项语法/链接/hash检查。测试具体结果记录到专项报告，不合并跳过项为通过。

## 4. 实际部署审阅门

明确主机/域名/Unix 用户/端口/目录/版本、数据库与存储实例绑定、恢复能力、迁移与停写顺序后，逐项取得目标授权。未授权不得创建服务、签发凭据、迁移、重启、改 DNS/防火墙或公开部署。启动时 Storage.recover 会写账本并清理到期/失败删除资产，须包含在目标授权中，不能称为只读启动。

## 5. 退出条件
