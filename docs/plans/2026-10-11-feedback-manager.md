# 反馈管理端 EXE、安卓 APK 与即时提醒

目标：井井在 Windows 与小米／红米 HyperOS 上查看同一反馈会话、回复文字和图片，新留言到达时收到系统提醒。用户端与已启用的邮箱投递保持现有行为。

界面复用现有管理端与主题。电脑采用双栏收件箱，手机采用会话列表与聊天详情两页，保留草稿、未读、已解决、图片预览与邮件状态。控制台、接口名称和密钥不进入日常操作页面。

Windows 独立工具仅冻结 Qt 宿主、管理端静态资源与反馈网络层，不带科研环境、模型、说明书媒体或管理员凭据。复用本机已有 DPAPI 身份，关闭窗口隐藏到托盘，双击再次唤起。新 EXE 采用工程外独立目录与 Windows-only PATH 核验最终字节。

安卓原生宿主加载同一管理页面，网络和权限在原生层处理。安装包不含管理密钥，首次由电脑端生成五分钟有效、一次使用的配对码，手机领取独立可撤销的随机凭据，以 Android Keystore 加密保存。设备授权记录采用反馈目录中的独立受保护 JSON 文件，不更改现有反馈库 schema 或迁移研究数据库。

用户新留言在原消息事务中生成持久即时事件，重试不重复。现有每天北京时间09:00检查保留。两端用现有HTTPS长连接补收通知，管理员回复同步刷新其他管理端。安卓采用用户开启的 remoteMessaging 前台服务与明确的常驻接收通知，提供通知、电池和小米后台设置入口；强行停止、禁用权限或厂商省电限制下不承诺即时提醒。参考[Android服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types#remote-messaging)与[通知权限](https://developer.android.com/develop/ui/compose/notifications/notification-permission)。

验收：配对过期/一次使用/尝试限额/撤销与权限边界，消息幂等和即时事件原子性；Windows当前源码与最终EXE，安卓构建/lint/独立模拟器中的查看、回复、图片、草稿恢复和后台通知；授权服务器只读预检后更新对应源码，保留SMTP/每日检查/原会话。小米实体手机现场通知单独记录，不能用模拟器结论替代。

## 回收站和实时未读标题（2026-10-16）

按用户追加要求：会话可移入回收站，在30×24小时内查看/恢复，满期永久清除消息、图片、来源事件与相关投递记录。保留邮箱验证身份与既有用户凭据，用户再留言时可开始新会话。回收站期间新用户留言自动恢复原会话，重复请求不视为新留言。确认操作绑定当前最后消息ID，有新消息时返回冲突，重复删除不延长到期时间。

回收站状态追加到现有events JSON，与消息同SQLite事务/写锁序列化，不迁移schema。回收站不计未读、不参与每日补查提醒，禁止管理员回复/改状态/重试邮件。正在投递的邮件拒绝移入，排队/失败的邮件取消并保留应用内消息；恢复不补发旧邮件。维护任务启动时和每分钟清理到期，读写相关会话时亦先清理。

用户截图的标题3条提醒由原notify只设置标题、不在已读时归零引起。新Windows桥依据当前服务器会话摘要发出原生未读状态，回收站排除；已读事务仅在状态改变时产生同步事件，避免刷新循环。历史SSE按当前未读重新核对，重连批量事件共用一次摘要查询，避免旧计数覆盖或阻塞界面。标题/托盘工具提示随当前数量归零。
