# M17 国际音标 Plus 详细规划

> 2026-10-02 实施更新：井井随后授权按本计划完整实施，并明确要求三表默认桌面单屏、VoQS 中文名严格采用指定知乎文章。当前 **verified，限定 Windows Chrome/实际 Qt 开发集成及报告所列范围**。500输入入口、56指定译名、固定字体、编辑/草稿、1366/1920默认单屏已完成。见 [验证报告](../testing/m17-report.md)、[手册](../manual/ipa-plus.md)、[ADR](../decisions/ADR-M17-client.md)。原规划中的待授权/布局审阅条款为历史停止点，已被后续完整实施授权覆盖。跨平台GUI、物理DPI/IME、极多短行吞吐与冻结发行未扩大为已验。

> 以下保留最初规划依据及其当时的事实边界。原文“本轮仅检查资料”指实施前规划轮次，不代表当前尚未实施。

**Goal:** 在同一 v3 页面切换 IPA、extIPA 和 VoQS，点击所有有意义的表项向底部大文本框输入，支持手动编辑、全文复制、可关闭的详细介绍与随包固定字体。

**Architecture:** 完全在客户端运行的版本化符号数据、编辑器与静态说明资源。桌面和浏览器共用同一页面与数据，无 Python 科学计算、服务器任务、数据库 schema 或远程查询依赖。

**Tech Stack:** 既有 Vue 3／TypeScript、原生文本编辑与剪贴板能力、本地字体资源和小型本地草稿存储；必要时使用模块内字符渲染适配，不引入重型通用富文本编辑器作为默认方案。

**Status:** `verified`（上述限定范围），2026-10-02。M17已接入工作台；IPA244/extIPA191/VoQS65，共500入口。目录和来源清单已冻结，VoQS56原表中文项逐条对齐指定文章。网页冷启动离线缓存未实现，已明确为范围外。

配套独立规划：[M16 录音](2026-10-02-m16-recording.md)。

## 1. 本地运行结论

此模块很适合做纯客户端工具。符号、说明、检索、文本编辑、复制与草稿均在用户设备上完成。网站服务器只需提供静态页面和字体，不接收输入文本，不需要账号额度、任务队列或计算资源。

桌面 EXE 应包含所有资源，断网可用。网页首次加载需要取得资源；“页面加载后不再请求网络”与“关闭浏览器后离线重新打开”是两个验收条件。后者只有实现并验证版本化离线缓存／PWA 后才能承诺，本轮不把浏览器缓存碰巧命中视为完整离线发行。

建议与 M13 普通话转 IPA 并列，模块名称为“国际音标 Plus”。M13 继续负责汉字转换，本模块负责全表输入和符号说明，不能把两者的音标范围、草稿或快捷键混在一起。

## 3. 三张表的完整范围

### 3.1 IPA

必须包含肺部气流辅音、非肺部气流辅音、元音图、其他符号、附加符号、超音段、声调与词重音。每对清浊辅音分别可点击，元音图上的每个符号分别可点击。连音线、时长、重音、边界和声调记号也纳入，不能只做辅音／元音键盘。

官方空白格和阴影格保留对应含义，不创建没有官方来源的符号。位置标签与说明可中文化，并保留英文术语用于核查。

### 3.2 extIPA 2025

按用户完整表分成以下区块：

1. 额外辅音，覆盖表中各发音部位、方式及清浊／组合形式。
2. 附加符号，包括唇展、强／弱构音、部分去鼻化、鼻音逃逸、腭咽摩擦、偏侧、吹哨、重复、吸气和滑动构音等。
3. 节奏、停顿、强弱、速度与不确定性记号。
4. 发声相关标记，包括起始／结束／部分清浊化、前送气、无送气和长送气等。
5. 其他声音及组合例示。

这里的条目名只是范围指示，中文定名与说明在逐项审校时确定。例如表中 `partially denasal` 必须保留“部分”的含义，不能复用旧稿时误写成完全去鼻化。

独立附加记号和完整示例分开：点附加记号插入记号本身，点标明“示例”的按钮才插入带基底字母的整个组合。圈记号、带标签的大括号、双括号、`f / ff / p / pp` 及速度词都要有可用入口，不能因缺少单一码位就遗漏。

### 3.3 VoQS

覆盖气流类型、发声类型、喉位、喉上设置四个大区及原表组合，喉上设置继续按唇舌、软腭、颌与伸舌组织。另提供程度数字、大括号和组合示例工具。

2016 表中的组合符号是独立可点击项。不能只提供 V、F、W、C，再要求用户自行拼出图表上的全部组合。1994／2004 历史形式如保留检索别名，需要明确标为历史，不能与当前表并排造成同义误认。

VoQS 描写的是音质及其范围，不把点击一个标签解释成临床诊断。介绍中区分该符号所描述的设置、组合可能性和论文明确提出的限制。

### 3.4 “每一个符号可点”的验收口径

建立逐格覆盖表：`source → page → section → row/column → display_item → symbol_id → insertion_sequence → tooltip → test_id`。

- 表中有独立转写意义的符号／记号必须对应按钮。
- 一个格内两个音标对应两个按钮，不能整格只能插入第一个。
- 排版用分隔线、箭头引导线、版权标记、普通说明文字不冒充转写字符。
- 表中组合示例若保留展示，必须可点击插入其示例序列，且与独立记号入口明确区分。
- 未解决的码位／渲染项列为阻断项，不以图片可见代替文本可输入。全表验收前不标注“完整支持”。

## 4. 页面、输入和详细介绍

```text
工作台标签：国际音标 Plus
工具栏：[IPA] [extIPA] [VoQS]    搜索符号／名称／码位    [符号介绍 开／关]
┌────────────────────────────────────────────────────────────────┐
│ 当前表：真实可点击的符号按钮、分类标签、元音图／辅音表               │
│ hover 介绍延迟显示；必要时固定到说明侧板                            │
│ 高表格在本区域滚动，底部编辑框保持可见                              │
├───────────────────── 可拖动高度分隔线 ────────────────────────────┤
│ 大文本框：自由输入／粘贴／音标插入／撤销重做，支持多行               │
│                                                               │
├────────────────────────────────────────────────────────────────┤
│ 复制全部   全选   撤销／重做   保存文本   清空                      │
│ 草稿状态、当前符号码位、固定字体与资源版本                          │
└────────────────────────────────────────────────────────────────┘
```

这是待实现布局。遵守 [UI 规范](../design/UI_SPEC.md) 和 [公共模块布局](../design/module-layout-contract.md)，不再加重复模块页首与关闭按钮。初版可建议表区约占 65%、文本区约占 35%，并记忆用户调整；小窗下允许表格横向滚动，不能把符号缩小到难以点击。

三张表共享同一个文本草稿。切换表、筛选、搜索和说明开关都不清空文本、不移动已保存的插入点、不损坏撤销历史。清空只通过明确按钮执行，且可撤销。

搜索支持字符本身、中英文名称、别名、Unicode 码位与 CIN 编码别名。CIN 编码首版只用于检索／说明，不自动把用户打入的普通字母替换成音标，不开发系统级输入法。

### 4.1 点击插入

- 默认在文本框最后有效光标位置插入；有文本选区时，普通符号替换选区。点表格不会使插入点丢失后总追加到末尾。
- 初次打开没有历史光标时在文本末尾插入。插入后光标回到新文本之后，适合连续点选。
- 原生键盘输入、中文输入法、粘贴、换行、复制和撤销保持可用。组合输入期间不打断 `composition` 事件。
- 页面不拦截文本框空格为音频播放；与 M16 和全局播放热键严格按激活页面／编辑焦点分工。
- 每次符号点击成为一个可撤销的文本事务。需要处理程序插入与手工编辑共用历史的问题，不能只做 `textarea.value += symbol`。

### 4.2 悬停介绍

默认开启，建议延迟 350–500 ms，指针短暂经过时不弹出。浮层不抢焦点、不移动按钮、不遮住正在点击的相邻符号；长说明可固定到侧板阅读。键盘焦点与显式“查看介绍”也能打开，触屏可使用专门详情动作。

关闭开关后停止 hover 浮层与长介绍的自动显示，不只把浮层变透明。说明开关独立保存，切表后仍有效。关闭介绍不影响按钮的基本无障碍名称，不要用浏览器原生 `title` 留下无法关闭的另一套弹窗。

每条详细介绍至少包含：

| 字段 | 要回答的内容 |
| --- | --- |
| 名称 | 中文推荐名、英文原词；有争议译名列出别名与采用理由 |
| 分类 | 所属体系、区域、发音部位／方式或音质设置 |
| 具体含义 | 字母表示什么音，附加符号修饰什么，VoQS 覆盖什么范围 |
| 使用方法 | 基底前／后、附着位置、作用范围、程度数字或括号用法 |
| 示例 | 准确的组合或有来源示例，区分教学构造与文献例子 |
| 易混项 | 如 IPA 音段与 VoQS 音质、不同高度的字形、相似 Unicode 字符 |
| 输入信息 | 实际码位序列、组合字符说明、复制兼容性及 CIN 别名 |
| 来源 | 表格版本、页／区／格和文献链接，必要时解释历史差异 |

篇幅建议根据符号复杂度安排，简单字母约 80–160 个中文字，复杂记号可 150–300 字并展开详情。这是编辑目标，不用无信息的句子凑字数。不能声称全部中文术语已经规范统一。

## 5. 字符编码与编辑规则

### 5.1 显示字形与实际输入分开

一个记录需要有 `display`、`insert_text` 与 `insertion_mode`。禁止直接复制 PDF 的 ToUnicode 提取结果进入产品。

| 类型 | 展示 | 默认插入行为 |
| --- | --- | --- |
| 独立字母／间隔符号 | 字符本身 | 插入已核对的 Unicode 序列 |
| 组合附加符号 | 可用虚线圆展示位置 | 只插入组合字符，虚线圆不写入用户正文 |
| 表中完整示例 | 清楚标为示例 | 插入完整基底＋附加符号序列 |
| 成对括号／范围模板 | 用真实示例表示作用域 | 包住现有选区；无选区插入成对模板并把光标放在中间 |
| 跨两个基底的连线 | 显示真实两字母组合 | 按已审校字符顺序插入；有选区时只在合法长度条件下执行连接命令 |
| 无单一预组字符的记号 | 可由组合字符渲染 | 使用审校通过的序列；没有可靠文本形式时先列为待解决 |

附加符号无可附着的前字符时提示其用法并允许保留原字符输入，不暗中补入一个会污染正文的可见占位字母。可选的“应用到选中字母”工具与普通插入分开，避免选多个字符时不明确改写。

### 5.2 Unicode 稳定性

- 存储原样 Unicode 字符串与 UTF-8 导出，不全局执行 NFKC，不自动合并外观相似字符。
- 不对用户自由输入强制 NFC／NFD；catalog 的标准输入序列可经审校固定，查重另用比较键。
- 编辑器要理解 UTF-16 位置与 Unicode 码点／字素簇的区别，不能从代理对中间切开补充平面音标。
- 按字素簇移动／删除／选区时需保证组合附加符号不会被意外拆散；同时保留高级查看码位和单独删除附加符号的方法。
- 括号包裹、跨字符连线、上标和部分清浊记号用专门样例测试。不能假设字符 cmap 存在就说明整串排版正确。
- 若字体要求特定 OpenType 功能或连线编码顺序，记录在 entry 的渲染策略中，实际复制文本与展示保持可解释的一致。[SIL 连线与组合支持更新](https://software.sil.org/doulos/history/)。

### 5.3 CIN 清理

已发现两个旧 SIL 私用区字符：`U+F267` 和 `U+F268`。SIL 官方版本说明分别给出标准字符 `U+1DF06`、`U+1DF04` 的迁移关系，当前项目字体也含这两个标准码位。[Doulos 版本记录](https://software.sil.org/doulos/history/)。

新符号按钮优先输出标准码位；CIN 原文件只读保留，记录旧编码为检索别名和来源。用户自己粘贴的历史 PUA 文本不自动改写，可提供显式转换预览，不能把编码迁移变成不可撤销的静默替换。

另外核对数学斜体 `𝑓 / 𝑝`、普通 `f / p` 的排版与语义，以及圈字母、组合圈与 VoQS 上标。外观相似不等于 Unicode 语义或复制行为相同。

## 6. 固定字体与打包方案

### 6.1 当前已确认事实

项目已包含 `frontend/src/assets/DoulosSIL-Regular.ttf`，本轮读取字体 name／cmap 表确认是 **Doulos SIL 7.000**。全局 `frontend/src/design/fonts.ts` 已把 IPA 固定为 Doulos SIL。

本轮用标准库只读解析该 TTF，并与 CIN 输出的 346 个不同字符比较，发现以下 **14 个字符没有 cmap 映射**：

```text
U+24B8 Ⓒ   U+24BB Ⓕ   U+24BC Ⓖ   U+24C0 Ⓚ
U+24C1 Ⓛ   U+24C3 Ⓝ   U+24C5 Ⓟ   U+24C7 Ⓡ
U+24C8 Ⓢ   U+24C9 Ⓣ   U+24CB Ⓥ   U+25EF ◯
U+1D453 𝑓  U+1D45D 𝑝
```

审计文件在本轮本地证据目录 `font-cin-audit.json`。这只是对 CIN 的码位检查，不能证明三张新表全部覆盖，也不验证附加符号定位。PDF 中还有 CIN 未必包含的新组合和补充平面字符，需加入完整字体测试串。

### 6.2 推荐实现

采用“固定、随包的字体组合”：Doulos SIL 作为音标主字体，补充一份经许可和实际 glyph 覆盖核验的固定符号字体，供圈字母等主字体缺项使用。必要的中文说明字体与 IPA 分开，沿用 UI 中文字体角色；底部混合文本允许中文正常显示。

- 字符按钮和编辑区的 IPA 主字体不可由全局英文字体设置替换，用户可调字号和文本区高度。
- 通过本地 `@font-face` 和受控字体别名加载；不用 `src: local(...)` 优先选择用户机器上的同名字体，不依赖 CDN／系统已有音标字体。
- 补充字体限于需要的字符范围或确定的 fallback 顺序，避免它覆盖 Doulos 已正确显示的 IPA。
- 补充字体候选先检查已有可分发资源，再从官方项目选择。新字体的名称、版本、文件哈希、许可证和覆盖表在 A 阶段冻结；本轮没有下载或安装字体。
- 字体载入完成后才进行表格布局与导出测量。载入失败给出明确状态，不能安静退回系统字体并显示“已就绪”。
- 打包检查应包含实际 EXE 资源提取后的哈希和离线显示。仅开发服务器能加载字体不算随包完成。
- 不安装系统字体，不修改其他模块字号／行高／字体。若字体文件需要修改或子集化，先核对保留字体名与许可证要求，再以新资源身份登记。

Doulos 的官方说明支持 IPA 与组合定位，并按 SIL Open Font License 提供。但它对 IPA 的支持声明不等于对所有 extIPA 2025／VoQS 组合都经过本项目验证。[Doulos 官方页与许可](https://software.sil.org/doulos/)。

### 6.3 复制后的边界

应用内打包字体能保证应用内显示。纯文本复制只携带字符，不会把字体文件安装到 Word、微信或其他软件。因此：

1. “复制全部”默认复制真实 Unicode 纯文本，并逐码点验证往返。
2. 文本框保留手工全选复制的备用路径；剪贴板权限拒绝不能清空文本或假报成功。
3. 首版支持 UTF-8 `.txt` 保存；浏览器下载只显示“已发起下载”，无法确认目标磁盘写入时不声称已保存。
4. 可把保形 SVG／PNG 导出列为第二阶段选项，解决分享时的外观一致性，不能用图片替代首版的可编辑文本。
5. 不承诺任何外部应用在没有合适字体时都能无差异显示；帮助说明提供字体名称、官方获取链接和明确的兼容性说明。

## 7. 符号库与说明资料结构

建议每个规范符号用稳定 `id`，图表位置作为独立 occurrence，同一字符在多个表中出现时共享基础字符信息，保留体系特有说明。

```ts
type InsertionMode = 'literal' | 'combining' | 'paired-span' | 'template';

interface SymbolEntry {
  id: string;
  system: 'ipa' | 'extipa' | 'voqs';
  section: string;
  display: string;
  insertText: string;
  insertionMode: InsertionMode;
  codePoints: string[];
  nameZh: string;
  nameEn: string;
  aliases: string[];
  descriptionZh: string;
  usageZh: string;
  examples: {text: string; noteZh: string; sourceId?: string}[];
  sourceRefs: {sourceId: string; page?: number; locator: string}[];
  status: 'current' | 'historical';
  rendering: {fontRole: 'ipa' | 'supplement'; strategy?: string};
}
```

这是数据契约示意，不是已实现文件。实际还需独立 layout／occurrence 数据，处理一格多按钮、元音图坐标、表注、符号组合模板、无障碍名称和素材许可。

必要校验：稳定 ID 唯一；所有 occurrence 指向已有 entry；必需来源／说明非空；`insertText` 与码位清单一致；无控制字符／未批准 PUA；历史项默认不混入当前表；有意义的表项均有入口；字体覆盖与真实整串渲染都有证据。

### 说明写作原则

- 表格负责官方标签，论文负责机制与修订背景，Unicode／字体文档负责码位和显示。不能把 Unicode 名称直接当作完整语音学定义。
- 中文说明独立撰写，不整段复制论文或知乎文章。中文译名有歧义时明确推荐名及理由。
- 气声／耳语化、紧喉／粗糙音质等容易混淆的项目需要相邻项对照，解释语境，避免相互循环定义。
- 历史／新增／替代关系单独标注，不把旧 CIN 所含字符自动视为当代表上的标准。
- VoQS 特殊字形要查 Unicode 修订材料。例如 U+A7F8 的 petite-capital 字形问题已有专门提交，验证应检查形状和定位，不能只看名称。[Unicode VoQS 修订材料](https://www.unicode.org/L2/L2020/20113-voqs-correction.pdf)。

## 8. 草稿、复制与失效处理

草稿使用独立键，例如 `ipa-plus.v1.<local-profile>`，内容包括 text、光标／选区、当前表、介绍开关、字号、布局高度与 dataVersion。不得复用 M13 或账号任务存储键。

- 输入后短防抖保存本机草稿，并支持手工保存文本文件。新稿自动保存失败时提示，文本留在当前编辑器，不显示已保存。
- 关闭页面的 dirty 判定应区分“未写入本机草稿”和“还未导出文件”，沿用工作台既有保存失败不关闭原则。
- 清空保留撤销入口；软件更新遇到未知草稿版本时保留原内容并提供导出，不自动重置。
- 页面仅有一个活动编辑器；跨窗口同一草稿要 revision 冲突检测或独立草稿实例，不能用最后写入者静默覆盖。
- 浏览器本地存储可被清理，因此 `.txt` 导出是可携带的明确保存途径；不需要将用户文本同步到服务器。
- 外部粘贴只接收纯文本，不执行 HTML、脚本或外链。含控制字符／不支持字符可提示并定位，不能未经允许删改任意用户文本。
- 资源版本升级后用户已有文本原样保留，展示当前 catalog 版本，不把词条修订自动应用到草稿。

## 10. 技术方案选择与代码落点

### 10.1 方案比较

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 结构化字符按钮＋CSS／SVG 布局＋纯文本编辑器 | 可搜索、可访问、可测试，真实文本易复制 | 需要逐项编码和布局核对 | 推荐 |

## 11. 分阶段实施

所有阶段当前为 `planned`，先解决资料与码位，再完成 UI 与打包，不以三张截图代替输入功能。

### M17-A：逐表清单、编码与字体准入

1. 对官方 IPA、用户 extIPA 2025、VoQS Figure 2 建立完整 occurrence 清单。
2. 解析 CIN 候选并保留多编码关系，核对现代码位／PUA／组合序列。
3. 对每个条目记录来源位置和状态，先输出缺项、歧义和历史项报告。
4. 用完整字符集筛选补充字体，固定来源／许可／版本／哈希。
5. 在独立 Chrome 和实际 Qt 渲染每个单符号和组合字符串，并复制回读。
6. 提供统一 v3 风格的表区／文本区布局预览。

**退出：** 全表覆盖清单形成，码位和字体难点有明确处理方案，未解决项不能藏在“字体以后再处理”中。

### M17-B：说明与数据审校

1. 为每项写中文介绍、英文标签、用法、示例、区别和出处。
2. 校对版本差异、术语选择、组合位置和历史形式。
3. 建立 catalog schema 与自动数据检查，拒绝控制字符和无来源表项。
4. 对照原表逐格核对可点击单位，冻结首版 entry／occurrence 数量。

**退出：** 全部有意义表项映射到数据，所有自动说明都能追溯来源；未定译名明确列出。

### M17-C：纯文本编辑与输入事务

1. 实现选择区保持、literal／combining／paired-span／template 插入。
2. 将按钮插入、手工输入、粘贴、IME、撤销重做纳入一致的编辑事务。
3. 实现全文复制、失败反馈、UTF-8 文本保存和草稿恢复。
4. 测试补充平面、组合附加符号和长文本，不拆坏代理对或字素。

**退出：** 点击后插入位置、字符序列和一次撤销都正确，中文输入和系统快捷键不受破坏。

### M17-D：表格页面与工作台集成

1. 实现三表、分类、元音布局、搜索与所有按钮。
2. 实现介绍开关、延迟显示、详情展开、键盘和触屏入口。
3. 接入固定字体、字体失败反馈、双区拖动高度和浅深主题。
4. 串行接入导航、保存关闭、草稿隔离和播放快捷键排除。

**退出：** 页面内完整输入闭环成立，切换不丢文本，150% 页面缩放和窄窗仍可用。

### M17-E：全表回读与发行准备

1. 自动遍历每个可点击项，比较预期 Unicode、复制回读和草稿重开内容。
2. 逐页人工视觉核对全部图表与复杂组合，测试实际 Qt 的字体／IME／剪贴板。
3. 在无系统 IPA 字体的隔离配置中验证随包资源，测试断网及网络请求。
4. 更新手册和来源，检查打包资源清单与字体哈希。
5. EXE 实际构建和发行由后续明确授权控制；纯文本复制之外的保形导出可另列后续增强。

**退出：** 全表覆盖、编辑、资料、显示、离线和复制的证据齐全才可对相应平台标 verified。
