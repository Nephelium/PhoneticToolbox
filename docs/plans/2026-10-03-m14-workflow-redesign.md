## 2. 版式与交互方案

推荐保留四步导航，将每一步的编辑内容完整放入中央工作区。全局导航和标签栏沿用现有组件，左侧保留步骤与当前文件信息。导入参数只在第 1 步出现。第 2、3 步拥有贴近编辑对象的保存操作。生成、保存文件和下载集中在第 4 步。右侧任务栏按需使用，前三步不保留一大块空白结果区域。

另两种方案的取舍：把所有内容合成一张长表会混淆导入、归并与输出；为每一步创建独立工作台会重复导航和状态。均不采用。保留四步导航也便于井井按既有习惯操作。

### 第 1 步：导入

```text
左侧：四步导航、当前文件、导入参数
┌────────────────────────────────────────────┐
│ 选择文件 / 更换文件         文件名与格式     │
│ 工作表或表格选择                           │
│ 字头 [第 1 列] IPA [第 2 列] 备注 [第 3 列] │
│ 数据从 [第 2 行] 开始       备注可选“不使用”│
├────────────────────────────────────────────┤
│ 原始表格样例：行号、列号、选中列着色       │
│ 1 │ 字头 │ 音标 │ 备注                    │
│ 2 │ 妈   │ ma55 │                         │
├────────────────────────────────────────────┤
│ 读取反馈                    [确认导入并继续]│
└────────────────────────────────────────────┘
```

- 文件选择后先读取有限的原始表格样例，让用户看见列号、表头和原始行号，再确认映射。这个样例仅用于选列，不出现导入与归并审阅或声韵结果。
- 字头/IPA 列必选且不能重叠。备注可选任意一列或不使用。列号和开始行均从 1 计数，越界在当前字段提示。
- 用明确的“数据从第 N 行开始”替换单一“跳过首行”开关。显示将忽略的前置行范围，默认从第 2 行开始。
- Excel 可选择工作表；DOCX 可选择表格。更改选列、开始行、编码后刷新样例，确认导入才替换已有研究数据。
- 当前代码实际上已经支持 XLSX、XLS、CSV、TSV、TXT，五种格式均在选择器和说明中明确列出。本轮新增 DOCX 表格导入，复用已有 python-docx 依赖。纯文本支持明确选择分隔符和 UTF-8 / GB18030 / UTF-16 编码，BOM 可识别，不使用丢字符式解码。
- 原始数据、空字段、引号内逗号及换行均须保留。缺字头或 IPA 的记录列明原因。检查多列表格、空备注、重复记录和格式损坏。
- 原有单辅音策略继续提供，名称说明清楚，不因导入选列变动而悄悄改变默认值。

### 第 2 步：调类与调值

```text
┌────────────────────────────────────────────┐
│ 调值与调类             6 个调值 / 编辑状态  │
├─────────┬───────────┬──────────┬───────────┤
│ 顺序    │ 原始调值  │ 调类名称 │ 条目 / 例字│
│ ↑ ↓ 01  │ 55        │ [阴平]   │ …         │
│ ↑ ↓ 02  │ 35        │ [阳平]   │ …         │
├─────────┴───────────┴──────────┴───────────┤
│ 同名调类归组提示、未保存修改数量           │
│ [还原本次编辑]        [保存调类设置并继续] │
└────────────────────────────────────────────┘
```

- 直接在当前页面编辑调类名称和顺序，无编辑弹窗。
- 保留拖动排序，增加上移/下移按钮供键盘与精确操作使用。按实际调类分组显示统计与例字，统一输入高度、表头与行间距。
- 保留原调值供核对，同名调类合并，空名称回退原调值并清楚提示。
- 页内编辑草稿与已保存设置分开。切换步骤保留未保存输入，生成前要求先保存；还原只撤销本次编辑。保存失败时不丢输入。

### 第 3 步：声韵排序归并

```text
┌──────────────────────┬─────────────────────┐
│ 声母 · 数量 / 搜索   │ 韵母 · 数量 / 搜索  │
│ 紧凑音标格、选中状态 │ 紧凑音标格、选中状态│
│ 拖动 / 上移 / 下移   │ 拖动 / 上移 / 下移  │
├──────────────────────┴─────────────────────┤
│ 当前选择 → 归并目标 → 受影响记录数/例字    │
│ 已归并关系：原符号 → 最终符号   [撤销归并]│
├────────────────────────────────────────────┤
│ [还原本次编辑]        [保存声韵设置并继续] │
└────────────────────────────────────────────┘
```

- 声母、韵母双栏，窄窗改为上下排列，各列表独立滚动。音标格使用统一选中、悬浮与焦点样式，保留 Ctrl/Meta、Shift 多选和整组拖动。
- 归并目标、预期影响和确认操作均在页面内完成，无独立弹窗。
- 展示链式归并的最终目标，禁止自归并和循环，支持撤销已做归并，避免误操作后只能整页取消。
- 原字头、IPA、备注保留。这里仅显示音类及局部例字，不显示完整的导入与归并审阅表。

### 第 4 步：结果

```text
┌────────────────────────────────────────────┐
│ [声母 → 韵母] [韵母 → 声母] [二维声韵表]  │
│ 搜索字头或 IPA [                  ] [↑][↓]│
│ 搜索范围 [字头/IPA/全部]    第 1 / N 个命中 │
├────────────────────────────────────────────┤
│ 当前预览：两种分组文档视图 / 二维矩阵     │
│ 命中高亮，自动展开分组并滚动到对应字项   │
│ 矩阵固定声韵表头，支持横向与纵向滚动     │
├────────────────────────────────────────────┤
│ 导入与归并审阅 [展开/收起]                 │
│ 总数/跳过/重复/原始IPA/声韵调归并及来源行 │
└────────────────────────────────────────────┘
右侧任务栏：生成三份结果、生成状态、当前文件保存/下载、保存全部
```

- 三个主按钮分别对应两份 DOCX 与二维 XLSX 的内容视图。分组方向、调类顺序、备注、重复条目和组内顺序与实际文件一致。二维表保持现有“行=韵母、列=声母”。
- 显示可搜索的结构化文档内容，排版适配当前窗口，不声称精确复制 Word 的纸张分页。三种视图都覆盖完整结果，不能仍限于前 200 条。
- 搜索支持字头、原始 IPA、归并后的 IPA，组合字符按规范等价匹配。输入后显示命中总数，上一项/下一项定位并高亮，矩阵定位到对应单元格与字项，清空搜索恢复完整视图。
- 大表采用分页或虚拟渲染，搜索始终索引全部记录，不只搜索屏幕上已渲染的内容。定位结果有明确的声母、韵母和调类信息。
- 导入与归并审阅只在第 4 步显示，放在结果预览下方作为可折叠区，默认收起。完整审阅表支持分页和定位到来源行，保留跳过/重复诊断。
- 未生成时显示当前设置的预览状态；生成成功后，三种预览绑定生成时的输入、设置和算法版本快照。随后更改设置，旧成果标明“设置已修改，需重新生成”。旧文件保留且明确其版本，不能混用新映射和旧输出。

## 3. 当前已复现的问题

下表前四项的输出来自当前工作区的 `.venv/m14/Scripts/python.exe -B`，直接调用当前纯核心与导入函数，无产品源码修改。结果快照问题来自静态源码检查，尚未进行 UI 复现。

| 项目 | 输入/触发 | 当前实际结果 | 拟修复与边界 |
| --- | --- | --- | --- |
| 连音符切分 | `t͡s55`、`t͜s55` | 声母 `t͡` / `t͜`，韵母 `s`，两种单辅音策略结果相同 | 连音符连接的塞擦音视为完整单位，两种单辅音策略分别生效；保留原始字符串 |
| Unicode 等价元音 | `ã35`，空韵策略 | 声母 `ã`、韵母为空；而 `ã35` 为零声母、韵母 `ã` | 规范等价识别，预组/组合形式不能改变元辅音身份；不对全部 IPA 使用会改变修饰字母的 NFKC |
| 等价写法形成两个韵母 | `tsã35` 与 `tsã35` | 分别得到 `ã` 与 `ã` | 分类与搜索按规范等价对齐，原始 IPA 留作审阅 |
| TXT/TSV 空列错位 | `\tma55\t备注`，字头缺失 | 接受为字头 `m`、IPA `备注`、备注 `a55` | 保留空列，按选中列取值；缺字头应明确跳过，不制造伪记录 |
| 结果快照未失效 | 先生成，再保存调类或声韵修改 | 页面保留旧 `result`，审阅映射却更新 | 标记旧结果过期于当前设置，生成和预览绑定同一快照 |

还发现需要单列语义与覆盖的边界：

- `ɹa55` / `ɻa55` 当前都得到零声母，整个 `ɹa` / `ɻa` 进入韵母。原因是同一符号同时出现在元音集合和辅音优先集合，但辅音优先仅用于单辅音判断。修复时增加上下文用例，覆盖独立元音前的辅音用法以及单独成音节的策略；不可简单从一个集合删除就宣称解决所有语料。
- `ma⁵⁵` 当前得到调值 `0`、韵母 `a⁵⁵`。现有手册限定末尾普通数字，这属于输入支持增强，应明确支持尾部上标数字，不把原有未支持输入伪称为已支持。声调字母及多音节串另行诊断，不能把内部空白简单删除后当作一个音节。
- 科研解析行为会变化，需记录新的 computation revision 与例子。旧草稿、旧任务和旧结果保留旧语义标识，载入后显式提示重新分析。原 V2 基准保留，不靠覆盖预期值掩盖本轮变化。

5. **结果一致性**：由共享的结果分组模型驱动两份文档、矩阵和前端预览，核对完整条目、顺序与重复项。输出交付仍为两份 DOCX、一份 XLSX，内部预览数据不作为第四份交付文件。
