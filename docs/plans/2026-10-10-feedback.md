# 用户反馈与独立管理工具实施计划

**当前状态：** 用户提供更新后的客户端授权码，服务器已接通 SMTP，新用户首次验证联系邮箱，无需注册账号。此前未验证的会话保留原凭据与历史，可在反馈页验证联系邮箱后升级；不自动补发暂停期间的旧回复。真实验证码收件、Ubuntu隔离回复队列的文本与图片附件收件均已核验。SSH 登录信息按用户授权保存在本机 Windows 凭据管理器，源码两端、公网API和Linux日程已验收，冻结包完整反馈矩阵另列未验。

**Goal:** 用户首次邮箱验证后通过关于页持续提交文字与图片，管理员用独立 Windows 工具回复，服务器每天推送新增反馈提醒，回复同时进入应用会话与邮件队列。

**Architecture:** 复用 Vue 主题与 Qt 静态资源宿主。反馈 API 是统一后端的可选组件，也可作为现有站点的独立部署能力，不依赖科研任务数据库或账号注册。独立 SQLite 反馈库保存邮箱身份、凭据摘要、消息、私有图片、邮件 outbox 与持久通知。服务器拥有日程，管理员工具建立 HTTPS 长连接接收推送。

**Tech Stack:** 现有 FastAPI、SQLite、Pillow、Vue、TypeScript、PyQt6、Python SMTP_SSL/STARTTLS，无新增全局依赖。

## 授权与边界

- 2026-10-10 用户确认整体实施和服务器每日检查；通知进入单独工具，禁止创建 Codex 定时任务。
- 用户指定 sendemail.py 作为发信配置来源，并已将登录密码改为客户端授权码。只静态解析所需设置，不能导入或执行批量发信逻辑；凭据不进入源码、包、日志或报告。脚本内原腾讯服务器地址已过时，部署输入按[校方当前配置](https://inc.sysu.edu.cn/cat/165)使用网易SMTP地址，未修改外部批量脚本。
- 新反馈库与科研库分离，不迁移现存研究数据，不改相邻 v2，不 push 或公开发布应用。
- 真实服务器连接与部署配置先只读核验；没有可用连接则保留可部署代码、明确列出现场未验项目。

## 步骤与文件

1. backend/src/ptb_api/feedback.py、feedback_mail.py：邮箱验证码、失败限额、随机凭据、隔离会话、图片解码重编码、消息幂等、回复和邮件原子落库、重试、每日提醒与持久推送。backend/tests/test_feedback.py 覆盖隔离、过期、并发、重启、重复和失败。
2. desktop/src/ptb_desktop/feedback.py、feedback_bridge.py：固定服务地址、无重定向 HTTPS、本机受保护凭据、错误不泄露私人配置、QWebChannel、通知线程与关闭；接入 host.py。
3. frontend/src/platform/feedback.ts 与组件：关于入口、邮箱验证、聊天、图片、发送状态、草稿及未读。frontend/src/feedback-admin/：独立管理页面、会话列表、回复、状态、邮件投递反馈，复用公共主题。
4. desktop/src/ptb_desktop/feedback_manager.py、scripts/start_feedback_manager.py 与 PowerShell/双击入口：独立 Qt 工具、托盘通知，默认不包含管理员凭据。
5. deployment/feedback/：服务器入口、systemd/反向代理模板、私有 SMTP 配置适配与说明。日程在服务器，离线提醒持久保存，邮件投递立即排队。
6. Windows 定向 pytest、前端类型/测试/build、独立浏览器和 Qt、真实 HTTP/SMTP 本地回执、文档与架构检查。实际服务器、真实邮箱、最终 EXE 分别记录，不把本地通过扩展为生产完成。

## 验收

- 无注册页和用户密码，首次验证邮箱后可恢复并持续交流。
- 用户只能访问自己的消息和图片；管理员认证独立。
- 同一条消息重试不重复，回复落库后即使邮件失败仍能在应用读取。
- 一天至多生成一次新增留言通知，重启不重复，管理工具离线后可补收。
- 服务日志不保存凭据、邮箱、正文或完整 IP；图片去除元数据；反馈不套用科研三天清理。
- 服务器未接通时界面保留草稿、明确显示连接状态，不伪装已经提交。
