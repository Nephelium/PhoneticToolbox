# 发声类型合成模块设计

## 目标与边界

将独立“基频 / 发声类型重合成工具”的用户功能原生集成到 PhoneticToolbox，主页入口命名为“发声类型合成”。迁移以源 Python 实现为功能基准，不复制、启动或依赖原 EXE，也不把原脚本整体塞入 GUI。

首版保留以下能力：选择源/目标 WAV；Parselmouth/REAPER F0 提取；首尾静音裁剪；LPC 逆滤波与声门脉冲检测；源/目标 F0 曲线显示和控制点编辑；仅改变 F0、仅改变发声类型、同时改变二者三种连续统；正反两个方向的全部连续统生成；分步 WAV、拼接 WAV 与编辑后 F0 CSV 导出；原工具全部可调参数和帮助说明。

不迁移论文统计复现、论文原始数据和示例输出目录。这些属于源研究项目，不是桌面工具的运行依赖。算法仍明确标注为基于 LPC 残差信号的近似重合成，不能把结果描述为发声生理机制的直接还原。

## 架构

依赖链保持 `GUI -> Services/API -> Core/Models`。`models/phonation_synthesis_models.py` 定义配置、分析结果、连续统类型和导出结果；所有默认值只在模型层维护。`core/manipulation/phonation_synthesis.py` 接收 NumPy 数组，承担静音检测、LPC 残差、脉冲检测、F0 控制点插值和连续统合成，不读取文件，也不依赖 PyQt6。

`services/phonation_synthesis_service.py` 负责 WAV 读取、重采样、临时 WAV、复用现有 Praat/REAPER、输出目录与 CSV/WAV 写入。`gui/workers/phonation_synthesis_workers.py` 在后台线程执行双文件分析和连续统生成，并通过进度、完成、错误、取消信号与界面通信。`gui/widgets/phonation_synthesis_widget.py` 只收集参数、编辑表格、绘图和呈现状态。主页负责单实例窗口生命周期与主题传播。

## 数据流与错误处理

源/目标 WAV 由 Service 转为单声道浮点音频并重采样到 11025 Hz。初次 F0 决定有声分析边界，LPC 逆滤波产生残差；残差再次提取 F0，用于周期定位和连续统。编辑后的 F0 轨迹只替换分析结果中的 F0，不重复修改原始文件。生成阶段在源时长、源声道滤波器和源边界上工作，目标提供 F0 轮廓或残差周期形态。

所有参数在任务启动前统一校验；文件不存在、F0 范围倒置、帧移不小于窗长、脉冲窗顺序错误、无有效有声区或脉冲不足均返回中文错误。长任务不在 GUI 主线程执行，关闭窗口时先请求取消并等待线程安全结束。输出只写入用户选择的目录，不覆盖源 WAV；同名连续统目录中的既有 step 文件会由本次明确生成的同名文件覆盖，但不删除其他文件。

## 验证

Core 使用合成信号做确定性单元测试，覆盖参数校验、静音裁剪、LPC 数值有限性、F0 编辑和三种连续统端点。Service 使用临时 WAV 和可替换 F0 提取器测试分析、输出命名、CSV 与错误传播。GUI 做离屏构造、入口、主题和后台任务状态冒烟；随后在高 DPI 下分别截图检查暗色/亮色布局、中文字体、表格和图像区域。

最终在 `phonetic_311` 环境运行定向测试、完整 pytest、compileall、主窗口构造、资源检查和 PyInstaller onefile 构建。打包后从非项目目录启动 EXE，确认新入口可打开，Parselmouth 与 REAPER 均能分析示例 WAV，并检查程序退出后没有遗留本任务创建的进程。
