# M11 独立组件交付

## 目标与范围

沿用 Windows x64 MFA 3.3.8、既有 CPU 对齐算法和模型兼容检查。用户授权本地整理组件包、简化安装入口，并确定官网固定路径 `/releases/components/mfa/3.3.8-r1/`。上传由用户另行操作，本任务不部署服务器、不更新现存数据库、不改系统环境。

普通入口为从官网下载并安装、选择已下载 ZIP、选择已解压组件文件夹。三种入口共用验证和实际 MFA 探针。旧版环境接入放入高级选项，模型与词典仍可单独替换。根据追加要求，提供两个按钮打开官方模型/词典目录，保留默认配套资源说明。应用瘦身、增量更新和缓存回收仅作当前成品与代码的只读可行性核查，见 `docs/testing/package-size-review.md`，不实施整体架构改动。

## 方案

单 ZIP 内含 `env/`、配套 `models/`、组件清单、使用说明及第三方材料。程序内置固定版本的包摘要和清单摘要，不要求用户手填 JSON 或 SHA-256。网盘只负责传送同一个 ZIP，不增加网盘自动登录或爬取。

相比继续让用户分别选清单，内置摘要能保持来源绑定并简化操作。相比完全信任 ZIP 内自述，内置摘要可以拒绝被替换的可执行环境。新组件身份须通过应用发布更新。

在线与 ZIP 导入复用安全展开和最终路径自检。文件夹导入先核对内置清单摘要和完整文件集合，逐文件校验后执行探针。失败保留原登记，不自动删除原有组件或用户文件。目录内可再生 Python 缓存不作为可执行环境的可信来源。

## 验证和交付

覆盖摘要损坏、未知包、路径穿越、平台失配、断网/HTTP 错误、失败保留登记、无需先选模型的首次安装、ZIP 与文件夹真实公开对齐、前端安装交互和浅深主题。运行环境与新 EXE 分别记录，未构建新 EXE 时明确现有 EXE 不具备新入口。

交付保留最终组件 ZIP、上传说明、版本身份和必要来源材料。许可/对应源码缺口按实际清单列出，不用 MFA 本体 MIT 代替整个环境的再分发要求。状态与证据原位维护台账及验收报告。
