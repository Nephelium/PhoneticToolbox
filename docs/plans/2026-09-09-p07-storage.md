# P07 配额、到期与资源管理实施计划

2026-09-09，井井在 P06 验收后回复“好，请继续～”，授权推进 P07；又在具体存储表与合成文件清理审阅后回复“好，继续”，授权该范围，003 已执行并通过首轮真实数据库/磁盘检查。整体状态 in_progress；该已授权范围内的复验不再询问。

**目标：** 网页用户的私有文件在真实磁盘与 PostgreSQL 中按 5,000,000,000 字节计量，提供上传、下载、直接删除和 7 天到期回收。

**架构：** 沿用 PG 与本机私有目录、已有账号/项目，拒绝未经受控 writer 的文件任务。网页生命周期不应用于桌面用户自己的本地文件。先完成可独立审阅的资源存储闭环，再联合 P06 接入生成/归档与输入引用；这些联合项不被单文件验收替代。

**技术：** 现有 Python 3.11/FastAPI/psycopg、标准库文件 API、Vue/TypeScript；无需新增全局依赖。使用现有独立 worktree，执行沿用项目固定流程。

## 方案比较与采用

- 采用 PG 账本与受控分块文件写入：能够逐块预留/结算，失败后按实际尺寸恢复。
- 只在结束后计量不能满足未知大小与崩溃覆盖，排除。
- 对象存储/文件系统配额适合后续原生外部工具，但本机尚无已验证环境；不新增这类依赖，也不开放任意目录写入。

## 第一批：可审阅的存储闭环

1. 新建 backend/migrations/003_storage.sql；quota_accounts 与 assets（含预留、已结算字节、状态、幂等键、截止及删除重试）和有限状态审计。所有表在独立 ptb_storage schema，无 DROP/ALTER，不迁移 P05/P06。
2. 先写 backend/tests/test_storage_policy.py：额度边界、转账不重复、过期不续期、Range 和名字/路径拒绝；首次运行确认新模块缺失，再实现 quota.py 与 storage_models.py。
3. 实现 backend/src/ptb_api/storage.py：root 标记和跨进程文件锁、PG 短事务、先持久预留再写入、fsync 后结算、幂等 offset、最终 hash、受控逐块读、删除失败继续计费和重启清单核对。私有目录不挂静态服务，每个资源只有一个随机物理文件，最终化只改变数据库可见状态，避免重命名/复制双份计费。
4. 实现 assets.py 与现有宿主集成；JSON 仍有 16 KiB 上限，文件块最多 256 KiB，不用 multipart 临时落盘。接口无配置明确 503，桌面返回 404。下载逐块重新检查会话/归属/截止，使用 attachment/no-store，不依赖 FileResponse 一次性检查。
5. 新建 backend/src/ptb_worker/cleanup.py：启动恢复先核对再开放写入；周期回收失败暂存/到期/主动删除，删除成功才释放已占用字节。提前 60 秒只调度，不提前删除。异常保留错误与占用，未知文件使写入冻结，不能直接释放预留。
6. 新建 frontend/src/account/ProjectStorage.vue：账户空间与预留、按大小/截止排序的资源列表、分块上传进度、下载、带影响说明的直接删除和失败重试；沿用公共 ModalDialog 和主题。切账号/项目卸载并中止请求。
7. scripts/p07_database.py 与 scripts/verify_p07_storage.py 提供独立迁移审阅与真实 PG+文件验证入口，只有明确授权参数才允许操作。完成纯政策/HTTP 替身测试、类型/构建、生成契约、来源与文档检查后提交本地检查点。
