# 生理参数合成浏览器 WebAssembly 实施计划

**目标：** 按井井本轮明确要求，将现有 VTL 2.4 及 m10/r18 几何修改编译为 WebAssembly，在用户浏览器执行，保持当前算法和功能，并与原生版本对照结果和性能。

**架构：** 优先在独立同源 Worker 中使用现有 Pyodide、原 Python Engine/Runtime、设备无关 BrowserAudio/MemoryProfile，以及同版本 C++ 的 Wasm 动态库。平台端口保留原界面、浏览器音频/文件和服务器回退。不得以界面呈现或仅编译成功代替完整迁移验收。

**技术：** 工程既有 Emscripten 4.0.9、Pyodide 0.29.3、VTL 2.4 C++14、NumPy、TypeScript Worker；工具链和中间物只在 output/validation/m10-wasm-20261018，无全局安装。取舍见 [ADR](../decisions/ADR-M10-browser-wasm.md)。

## 1. 编译与装载可行性

- scripts/build_m10_wasm.py 从锁定源码包和现有 build_m10_geometry.py --prepare-only 生成原版 API 与原样几何补丁构建；排除未使用的主机设备 SoundLib。
- 先用既有 Pyodide 验证 ctypes 装载、C++ 异常 ABI、合成/分析/几何三份状态隔离；不能隔离则改用独立模块实例与明确的外部库端口，科学算法不改写。
- 构建记录源码、补丁、工具链、编译命令、二进制摘要、依赖与许可。

## 2. 共用核心和浏览器端口

- packages/phonetic_core/src/phonetic_core/vocal_tract/native_resources.py 添加显式 emscripten/wasm32 资源选择，不更改 Windows/Linux 路径。
- 独立 vocal Worker 复用原 Engine/Runtime、BrowserAudio/MemoryProfile 和文档/监测算法。生命周期、取消、序列失效、账号/项目隔离和有界队列由外层管理。
- frontend/src/platform/vocal.ts 接可替换执行端口；本地运行时不可用时在会话开始前回退服务器。运行中失败不得在丢失构形/序列时静默切换。
- 现有构形、三类声源、33/65 截面、0.5 秒测试发声、关键帧/F0/静音/送气、JSON 导入导出、同步视频保持。服务器容量策略不因实验迁移而自动放开。视频编码可保留原服务器编码端口，但科学 PCM/帧必须由浏览器现有算法产生并明确验证计算位置。

## 3. 科学结果与性能

- 固定合成输入，对照原生完整几何/截面/声管/传递函数、模型参数/单位/采样率/帧数/时间网格和文档。包括 a/i/u、局部舌形、声门高度、侧通路、闭塞、三类声源、静音及送气边界。
- 纯数组先沿项目门槛 rtol=1e-7、atol=1e-10；原有原生回归不放宽。随机噪声单列随机数实现及种子影响，不能以波形不逐样本相同掩盖几何/声源偏差。
- 井井在首轮对照后明确接受 0.001 dB 及同量级的小浮点差异，要求忽略这类差异。报告继续保留原精度比较和实测值，将授权的显示取整/跨编译器微差与参数、时间轴、几何或功能改变分开。
- 记录冷启动下载量/时间、热态姿态更新、0.5 秒发声和序列预计算耗时、实时系数、Worker 内存、主线程响应、取消与退出恢复。性能数据注明实际硬件、浏览器和并发条件。
- 真实独立 Chrome 页面验证全部操作、浅深主题、重复播放、刷新恢复、取消和网络请求；设备与其他浏览器独立记录。
