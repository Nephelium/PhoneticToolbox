# 桌面重复预览优化实施计划

**目标：**减少 EXE 共用代码中相同输入的重复计算及等待中的相同请求，保持科研输出与权限检查。

**范围：**Windows 本机 SpectrogramSession、录音工程预览和桌面前端请求编排。沿用既有科学进程、串行队列与工程，不变更数据库、科研参数、格式或发行物。

1. 用合成双声道音频测量现有语谱图与录音预览重复调用，报告输出摘要、耗时及实际计算次数，临时工程进入 scratch。
2. SpectrogramSession 保存最近一次成功响应，键包含完整音频 SHA 与声道/范围/宽度。响应最多 512 KB，关闭及超时清除，返回独立对象。
3. RecordingService 仅保留最近一个不超过 4 MB 的预览，键包含工程/版本/片段/文件身份及全部视图参数。每次检查片段路径、大小、mtime/ctime，变化或关闭失效，失败不缓存。
4. 桌面请求只合并尚未结束的同参数只读调用。保留串行与 128 项队列上限，写操作建立合并边界，失败后可重试，不保存完成结果。
5. 定向验证相同输入复用、参数/数据变化、错误重试、缓存预算、关闭释放及写操作顺序。运行受影响 Python 测试、前端测试/类型/契约/UI 数据/构建及合成性能脚本。
6. 在既有性能报告追加当前源码结果，同步 CHANGELOG、项目状态与任务台账。源码验证与现有冻结 EXE 的证据分别记录。本轮不重打包或发布。
