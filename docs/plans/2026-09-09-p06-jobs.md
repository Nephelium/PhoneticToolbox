## 范围与决定

服务端 PostgreSQL 保存任务及有序事件；本机采用标准库 SQLite 适配保存相同任务模型，不要求安装 PostgreSQL。两者复用同一状态转换与执行器；桌面只通过原有自有 API 子进程访问，不导入后端。SQLite 的实际初始化与 PG 新表一并列入建表审阅。本阶段只开放明确标注的 pipeline_check：核心包对确定性字节计算摘要，验证执行链，不能宣称语音分析已迁移。无音频上传、文件生成和下载，结果仅为有限长度任务元数据；P07 文件预留/计费/到期接口实现前禁止注册写文件任务。

考虑过内存队列（无法可靠恢复）、额外消息中间件（增加运维与依赖），沿用总计划 PG 任务表；本地 SQLite 只替换事务和存储方言，不另写调度政策。源数据和配置不可变，随机幂等键限定 owner；同键不同内容返回冲突。同账号最多 1 个执行任务，全局默认 2 个，由部署配置控制；每账号最多 1000 条任务元数据。

## 状态与竞态

queued → running → succeeded/failed/cancelled；运行中取消先 cancel_requested。每次认领递增 lease_generation，提交必须同时匹配任务、worker、代数、未到期租约和截止。过期 running/cancel_requested 变 interrupted；不自动重跑。显式重试新建任务、保留 retry_of 和原始快照。提交与取消由同一事务序列化：先提交成功则取消返回已完成，先取消则不能成功。成功必须和完整元数据 manifest 在同一事务提交；不存在尚未写出的“成功文件”。事件序号与状态同事务保存，事件不含请求正文、文件系统路径或数据库错误。

PG 短事务使用调度 advisory lock 保护全局/每人槽数，认领候选使用 FOR UPDATE SKIP LOCKED；运行时不持有数据库事务。SQLite BEGIN IMMEDIATE 提供相同事务边界。每个任务使用独立核心子进程，私有 stdin 传快照、stdout 传结构化进度/结果；父进程消失的 EOF 结束子进程。worker 失去租约或收到取消时有限时终止自己拥有的子进程，旧结果不提交。
