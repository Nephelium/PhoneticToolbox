# 3.0.0 修复、打包与官网发布

用户本次明确授权：修复 GitHub 更新和超长路径，统一 3.0.0，构建并验收；上传官网应用、MFA 组件和更新清单，连接官网免安装及安装按钮。随后授权最新版截图与主页改进推送 main，并追加要求上传 GitHub Releases。只提交已审阅的明确文件清单，既有无关工作区改动保留。已结束测试的临时目录交由子代理核对并清理，无法删除的列出清单与供用户手动运行的预览优先脚本。

1. GitHub 历史资产仅忽略旧于当前版本的条目，新候选校验继续严格；实际混合列表回归。
2. 科学运行时采用进程私有、限所有者与 SYSTEM 访问的短 ASCII 联接入口；入口指向已校验原文件，第三方主动解析长路径的原生导入另用 Windows 扩展路径。主加载器使用同字节短 EXE 入口和运行文件联接，托管子进程对长工作目录使用同目标短入口；原路径缓存租约保持有效。保留数据位置、科学二进制和系统设置；普通/中文超长用户数据及任务路径的最终字节分别验收。
3. 同步 3.0.0 版本、生成说明书及前端、唯一快照构建。三种包同源，应用 EXE 同 SHA；按严格规则完成科学/GUI/启动/缓存/安装/换版验收。
4. 核对服务器既有站点、反馈和论文路由；先上传并校验固定版本资源，再原子发布 stable/preview 更新清单及两处按钮。验证公网摘要、Range 和实际应用更新解析。服务器凭据只用既有 Windows 凭据库，源码及日志不保存凭据。

范围、结果与未验项原位维护于 `RELEASE-3.0.0-PUBLISH` 台账和当前 Windows 发行报告。当前日期与目录使用客户端北京时间，实际源码冻结身份以逐文件摘要为准。另一台干净系统及实体设备不由本机自动验收冒充。
