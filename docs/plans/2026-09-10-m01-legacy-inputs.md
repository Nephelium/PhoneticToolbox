# M01-G 旧格式兼容入口

2026-09-10，本批次 verified（Windows 定向范围，见[实际报告](../testing/m01-legacy-report.md)）。井井在联合验收交付后再次要求继续，执行其已提出的 v2 功能完整保留要求。对应 M01-A08 / A39；不是 M02 全模块迁移。

## 决策与范围

- PKL：选择显式本机转换入口。解释 pickle 操作码及已知 NumPy 数值序列化结构，不调用 pickle.load、不导入文件指定的模块、不执行构造器。支持 v2 数值标量/数组和伴随 timestamps 文件的音频起点；只输出 M01 所需六个向量及对齐元数据。原始 PKL 中的 landmarks 等录像数据保留在原文件，转换文件不冒充完整录像迁移。限制输入 16 MB、操作数、深度和数值尺寸，独立 Windows Job 限制内存/时间。原文件只读；输出同目录新 .lip.json，已有文件不覆盖。网页接收转换后的 JSON。
- 历史参数表：使用单独可选 `legacy_result` 输入角色，不能与受验证的 `parent_result` 同时使用。选择即明确当前音频关联，不自动按同名推断。支持 XLSX / .ptb.sqlite / .ptb.sqlite3；只在现有受控切分子进程读取。现有原始音频来源校验规则不放宽；历史表输出清单记录表 SHA256、文件名及 user_associated_unverified 标记，不伪造原始分析后端/采样率。
- 保留原列、标签、非有限值及时间帧，不重估、不排序、不静默删除非法时间行。输入损坏、公式、结构/资源超限或时间不适合当前音频时，给出独立原因。CSV 留在 M02 历史格式清单，不从本轮 XLSX/SQLite 验收推断覆盖。
- 复用统一工作台、平台能力接口和 M01 持久切分任务。原本可信父结果模式仍保留；增加明确历史表关联模式。无需新增数据库表、依赖或独立页面服务。
