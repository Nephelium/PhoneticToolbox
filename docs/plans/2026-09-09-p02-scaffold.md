# P02 · 正式环境、包边界和契约

2026-09-09，井井试用 P01 后反馈“目前没问题，可以继续”，授权本轮 P02。状态：verified（Windows 包、环境与契约范围）。实际验收见 [P02 报告](../testing/p02-scaffold-report.md)。

## 入口与范围

P01 Windows 原型与人工试用通过，沿用独立 CPython 3.11.14、PyQt6/WebEngine、Vue/TypeScript。P01 来源风险已有记录；技术开发主线冻结不等于批准 GPL 组合公开发行，也不等于 Mac/Linux 实测通过。未明确许可的历史材料不进入 P02 包。

本轮交付可安装的 phonetic_core、ptb-api、ptb-desktop 三个包，正式前端构建入口，以及单一模型生成的 OpenAPI/JSON Schema/TypeScript。核心暂只提供真实版本元数据，不迁移算法或生成假结果。桌面包提供本地服务握手与退出检查入口；正式窗口与公共组件属于 P04/P06。

## 执行顺序

1. 记录原 v2 文件、Git 和已安装依赖；对照继承声明，列出差异。更新 ADR-013 与授权记录。
2. `.venv/v3-dev` 使用 P01 已验证的独立解释器；锁定 Python 传递依赖及 npm lock。根目录旧 pyproject.toml 不作为新安装入口。
3. 先建立针对采样整数、半开区间、有限值、缺失原因、轨迹长度/单调性和跨层依赖的测试，再实现最小模型及检查器。
4. 后端 Pydantic 模型是协议唯一手写源，导出审阅快照，前端类型由 openapi-typescript 生成。版本由各包发行元数据读取；应用发行版本集中在 release/version.json，再生成包配置。
5. 服务端与本地模式共用 API factory；仅健康和能力读取，尚无上传、用户数据或任务接口。桌面不导入 backend，子进程通过标准输入取得一次性会话配置，通过受控 HTTP 健康握手；仅监听 loopback，校验 Host/Origin/凭据。后续 P06 扩展统一任务生命周期。
6. 检查 Python AST、前端导入、旧路径与静态资源登记；用故意越界样例验证检测能力。构建 wheel、在新环境安装并从非项目目录运行。
7. 运行定向测试、契约重生成无漂移、前端 typecheck/test/build、实际双模式 HTTP/退出检查、来源登记和文档检查，保存报告后标状态。

## 验收命令

统一使用 `.venv/v3-dev/Scripts/python.exe`（下文简称 python）。

- `python -m pytest -c tests/pytest.ini tests/contracts tests/architecture backend/tests desktop/tests -q`
- `python scripts/generate_contracts.py --check`
- `npm --prefix frontend run contracts:check`、`run typecheck`、`run test`、`run build`
- `python scripts/check_architecture.py`、`python scripts/validate_docs.py`
- `python scripts/verify_p02.py`：干净 wheel 安装、非项目 cwd、两个服务入口及本地双实例退出，依赖锁核对。

## 退出边界

不安装全局依赖、不改 v2、不写数据库、不部署、不打包新完整 EXE。P03 数值基线、P04 正式 UI、P05 账号、P06 任务和 P12 发行各自保留；P02 通过不能替代这些验收。
