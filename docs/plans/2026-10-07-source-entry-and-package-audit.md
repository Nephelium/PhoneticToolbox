2026-10-07。井井已授权按讨论方案修改，并仔细检查打包内容。状态：verified，限定 Windows 源码、快照机制与既有包内容审计，见[报告](../testing/2026-10-07-source-entry-and-package-audit.md)。完整新 EXE 和依赖共享未实施。

## 目标与边界

开发时由一个启动器绑定当前工程的 frontend、desktop、backend 和 phonetic_core。模块脚本只指定初始模块，主进程与计算子进程采用相同代码来源。使用既有、经核对的主环境以及 EGG/LPC 和唇形依赖环境。原环境、用户数据、旧包和同期改动保留。

发行检查包括当前 EXE 的实际成员、原生和科学压缩包清单、构建输入及动态依赖。明确已排除、可以排除、需要运行验证和必须保留四种状态。先修复源码绑定和构建快照边界，不以删除科学库、模型、许可或验收工具换取更小的数字。此次不要求生成新 EXE。

## 实施顺序

1. 保存目标文件的本轮前状态，核对现有 m09-ui/m14 主环境的库版本与原生文件身份。
2. 建立统一 Python 源码启动器和只读检查入口，修改 PowerShell 模块入口，并阻止回退到已安装的旧业务包。
3. 核对普通任务、EGG/LPC、唇形和声道子进程的实际导入来源，验证启动异常及父进程环境恢复。
4. 构建器统一分析冻结快照，记录源码身份；审计实际发行成员，建立可复跑的体积与排除候选报告。
5. 更新项目规则、启动/发行文档和最终验证报告。

## 验收

- 模拟旧安装副本与外部 PYTHONPATH，当前入口必须绑定工程源码或明确失败。
- 所有正式开发启动脚本执行只读检查，不修改用户环境，不打开窗口或数据库。
- 真实子进程导入及当前主环境的代表性计算/文档导出。
- 项目所有 desktop/tests 必需检查及受影响的源码绑定/构建选择测试。
- 实际隐藏 Qt 启动、本地服务、模块入口与正常退出，采用本轮独立测试目录。
- 发行审计记录输入 EXE SHA、压缩与展开体积、候选列表和不确定项。源码验证不写成新 EXE 或干净实体电脑验收。
