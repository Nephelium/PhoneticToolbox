# 声源、喉部与声道的后续建模路线

2026-09-08。当前交付范围是浊声、无周期振动清声、耳语近似及驱动气压/声门几何控制。本文件记录井井提出的后续声带和完整喉部模型需求，不把后续阶段写成已实现功能。

## 当前可以复用的计算链路

当前程序通过 `vtlSynthesisAddTube` 使用 VTL 时域模型，已有“驱动压力 → 几何声门 → 声门与声道内气流/声压 → 口鼻辐射输出”的链路。它不是先生成一段独立周期声音再套静态滤波器。源代码中的几何声门接收跨声门压力用于确定振动幅度，TdsModel 计算声道负载和狭窄处噪声；但声带运动是规定的几何运动，不是组织受气动力后自行起振。

本地随包 `JD2.speaker` 实际选择 `Geometric glottis 2025`，另含 2019 几何声门和 Triangular glottis。`GeometricGlottis2025.cpp` 的相对幅度 `rel_amp=0` 可取消周期振动；`TdsModel.cpp` 的声门噪声源按气流/狭窄几何驱动。清声与耳语近似由这些原生参数生成，不在 Python 外加一条任意白噪声轨。

当前控制量使用 Pa、mm、mm²；原生接口分别使用 dPa、cm、cm²，转换集中在 Core。稳定气流不一定产生可听声音，闭合或无驱动压力应接近静音。气流速度/体积流量不是压力滑块的同义词，当前 API 未返回这些实时测量，因此界面不显示推算为真的 m/s 或 L/s。

## 建议的阶段

### 1. 先补喉部显示与真实计算遥测

在现有声学内核增加有限的只读输出：声门上下缘面积、膜部与后部缝隙、声带相位/位移、声门上下压力、体积流量、组织接触状态。数据必须来自**实际生成音频的那份原生状态**；目前几何 DLL 与合成 DLL 独立，不能拿另一份几何实例的振动相位冒充同步声带运动。

用这些输出驱动简化喉部显示，包括真假声带、声门、喉室、会厌上方通道；只有模型真实具备的可控部分才提供拖动点。先做同步低阶几何，再增加展示精度。当前头壳和平均鼻腔并非同一个体，新增喉部仍需明确参考配准的边界。

原生接口宜增加一条批量声学块及遥测返回方法，而不是按声学采样率跨 Python/JS 逐点调用。音频保持 48 kHz；可视化仅取有限帧率，跟随同一输出时钟。

### 2. 接入自振声带模型

优先在 VTL 现有时域声道模型中接入 Triangular glottis / 双质量模型，保留压力与气流的反馈。控制组织刚度、质量、阻尼、内收和气压，检查起振阈值、接触、开闭商、气流及声源谱。不能将“声带收紧”简单等同于提高 F0，内收、纵向张力、几何开度和组织刚度需要分开。

手绘 F0 在几何源中是给定频率；在自振模型中应变为期望轨迹，通过模型的刚度/张力或其自然频率控制实现，并展示实际达到的 F0。两种语义应明确区分，不能声称任意 F0 都能在任意气压/内收条件下实现。

现有声道面积函数已包含喉部上方的一段，接新模型前先统一声门接口平面、截面法向、长度、单位和声学参考点，避免将同一段喉腔计算两次。最重要的是双向压力/流量边界，不是把两个三维网格视觉上接在一起。

### 3. 高保真组织与流固耦合

如需由组织材料参数、三维气流与接触直接预测声音，需要体/覆盖层、有限元或其他连续介质模型和流固耦合。它可以作为桌面程序管理的独立求解器，但不应承诺在普通浏览器内以当前交互速度实时运行；更现实的是预计算、低阶代理与离线对照。

三维模型更细并不自动带来更可信声学结果。每阶段都需验证声门面积/气流波形、接触行为、源谱、共振峰和模型时间同步，再谈进一步的解剖精细化。

## 与主项目的接口边界

- Models：显式声源控制及单位、有效范围、模型类型与实际/目标 F0。
- Core：源模型、组织运动、气流/声学求解；注入只读资源，不访问 GUI 或用户配置。
- Services：独占计算实例、音频输出、缓存、遥测传输和本地子进程生命周期。
- GUI：控制输入与基于真实遥测的可视化；不得另行合成一份不同相位的“示意声音”。
