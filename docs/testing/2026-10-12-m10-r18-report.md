# 生理参数合成：局部舌形、常用构形与送气帧验证

2026-10-12，`M10-R18` 在 Windows 当前源码、原生几何 DLL 和独立 Qt 工作台范围内 `verified`。承接 [R17 下牙、下颌和真实波形修复](2026-10-12-m10-r17-report.md)。本轮未打包 EXE，未公开发布。

## 实现范围

- 舌根与舌叶之间增加舌面控制点，默认随构形移动，独立拖动形成局部平滑偏移。原生目标曲线以弧长定位控制站，偏移权重为 `16t²(1−t)²`，端点位移和一阶导数为零，然后沿用硬组织接触、重采样、截面和声管计算。零偏移不重建曲线，避免改变原有构形。
- 口底附着与舌尖之间增加舌底控制点。它改变可见舌腹组织的局部回接，端点保持，并受舌背、下颌和上下牙约束。该点没有新增舌下声学分支，不能据此解释舌下共振。
- 四维 `tongue_shape` 保存舌面前后/高低及舌底前后/高低偏移，单位 cm。范围依次为 `[-0.5,0.5]`、`[-0.3,0.8]`、`[-0.5,0.5]`、`[-0.4,0.4]`，属于当前模型的工程约束。缺省为零，重置舌头恢复为零，撤销、构形、关键帧和动态合成都保留偏移。19 项 VTL 参数顺序不变。
- 自存构形面板点亮内置与用户构形。设置常用分别列出两类构形，可独立点亮加入底栏，重名构形仍按 ID 区分。默认沿用原 11 个快捷起点，内置 s 可在库中选择，允许清空常用列表。常用列表独立持久化，不迁移现存数据库。
- 送气帧无需捕获独立构形，时长 0.01–3 秒。普通帧起始时刻作为姿势节点，送气帧占用的时间并入前后节点间的同一平滑过渡，仅在送气区间将声源切为清声。气压及其他声源参数继续插值。序列开头或末尾的送气沿用可用一侧的姿势，播放至少需要一个构形帧。
- 送气帧名称默认使用上标字符 **ʰ**，卡片内可直接修改，时间轴、文件与视频同步使用名称。名称与帧类型分开保存，改名不改变清声行为。音频块在送气边界切开，以边界时刻的声管作零长度声源更新，保持共鸣管状态；F0 图在区间内留白。
- 几何方法为 `m10/r18`，交换文件升级为版本 5，旧 1–4 版本保留参数并提示重算。本机构形文件版本 2、关键帧版本 3，旧字段缺省兼容；原生数组布局仍为 `m10/3`。

取舍与授权见 [ADR](../decisions/ADR-M10-tongue-transverse-and-floor.md)，使用方式见[模块说明](../../frontend/src/modules/vocal-tract/README.md)与正式说明书章节。源码变更涉及原生补丁/桥接、核心 shape/engine/trajectory/animation/document、桌面 profile/runtime/audio_output、前端控制点/构形库/关键帧/视频及来源登记。

复查入口在工程根目录运行：

```powershell
.venv/m14/Scripts/python.exe -B -X utf8 scripts/build_m10_geometry.py --output-dir output/validation/m10-r18/native-build
.venv/m14/Scripts/python.exe -B -X utf8 scripts/verify_m10_r18.py

node --test frontend/tests/m10*.test.ts frontend/tests/source-coverage.test.ts
```

Python 定向验证先调用 `scripts/workbench_source.configure()` 绑定当前源码，再调用 `pytest.main(['-o','addopts=','-q', ...])`。测试文件为 `tests/parity/test_vocal_r18.py`、`test_vocal_r15.py`、`test_vocal_tract.py`、`test_vocal_monitor.py` 与 `desktop/tests/test_m10_audio_output.py`。`addopts` 清空根工程的覆盖率插件选项，当前独立运行时没有该插件，未跳过断言。

验证过程中修正了三个问题：旧撤销快照应继续保留缺省字段，送气边界必须使用边界时刻的声管，以及重名的内置/自存构形需要独立常用选择。独立 Qt 新配置首次没有关键帧，测试误点禁用的清空按钮，已改为检查空列表状态后继续，失败诊断保留于 `qt-ed1d3be0662b483ba2a72cd34091859a`。说明书命令最初误传项目 JSON 路径，改用工程目录 `--project manual` 后验证与生成通过。
