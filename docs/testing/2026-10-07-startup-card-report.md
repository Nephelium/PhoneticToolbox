2026-10-07。井井要求启动准备界面带现有图标和应用名，使用楷体与 Times New Roman、美化进度条。

## 实现与状态

Windows 源码及独立冻结窗口 **verified**。完整应用 EXE/安装包 **尚未重打**，此前交付的 Cached-20261007-R4 保留。本轮没有公开发布、上传、push、安装全局依赖、系统设置变更、用户数据清理。

`desktop/src/ptb_desktop/startup_progress.py` 改为 Windows 原生圆角卡片，包含应用图标、PhoneticToolbox 名称、中文说明、实际阶段、实际百分比与蓝色渐变圆角进度条。无法确定百分比的等待和修复阶段显示往返动画，遵循系统动画偏好。准备完成后按原流程关闭。

中文请求 KaiTi，英文与数字请求 Times New Roman。本机实际回读字体为楷体与 Times New Roman。使用系统已有字体，缺失时允许系统回退，不分发商业字体文件。图标从 EXE 内嵌资源读取，来源仍为原 `frontend/src/assets/k2.png`，原图无修改。

窗口用 GDI 双缓冲绘制，支持按 DPI 缩放、DPI 变化后的圆角区域及图标重建，顶部可拖动。产品新增代码只依赖 Python 标准库和 Windows 自带接口；Pillow 仅用于独立验证程序截图。缓存划分、哈希校验、跨版本复用及解压逻辑没有本轮变化。

1. `frontend/tests/workbench.test.ts` 仍要求 17 模块、3 组，当前注册为 18 模块、4 组。
2. `frontend/tests/source-coverage.test.ts` 检出来源覆盖登记仍为 M01–M17，缺少新增 M18 对应项。

这两项不在本轮启动窗修改范围。未回滚同期模块、未改断言以制造通过，未启动会清理旧完整包的正式构建。[严格打包规则](../../release/PACKAGING_RULES.md)要求构建前完成前端检查及最终成品验证，所以本轮不标完整应用打包验收通过。相关模块完成后需按规则重新冻结、打包及验最终成品。

## 诊断与限制

首轮资源计数把 Windows 第一次调用图标/字体接口产生的进程级缓存误判为窗口泄漏，改为预热并等待延迟销毁后的连续窗口比较。随后一轮冻结验证记录 USER 对象从 34 降到 33，原“必须相等”断言产生测试程序异常弹窗；已读取错误并关闭本轮自有弹窗，检查改为验证对象数不增长，允许 Windows 延迟释放。验证程序异常现在写 `failure.txt` 并非零退出，不再依赖 PyInstaller 异常提示框。最终重跑通过，失败记录保留，没有变动产品缓存策略。

未验证另一台干净 Windows、缺字体的系统、实体跨屏 DPI/DWM、屏幕阅读器或长期运行。模拟 DPI 变化不等同实体显示器切换。此次只验证窗口显示，不据此声称首次启动性能改善；此前首次启动回退仍以[持久缓存报告](2026-10-07-persistent-startup-cache-report.md)为准。
