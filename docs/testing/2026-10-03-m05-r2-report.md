# M05-R2 本地录制、直接保存与面部放大

2026-10-03。状态：verified，限定本报告列出的 Windows 源码开发态、合成采集、真实编码/保存及 Chrome/Qt 范围。实体麦克风人声、摄像头、物理同步、DPI 和 Linux 媒体链仍未验。入口为 [Start-M05-Workbench.ps1](../../scripts/Start-M05-Workbench.ps1)，未生成新 EXE。

## 问题与修复

| 现象 | 定位与结果 |
| --- | --- |
| 有唇形，但录音近乎无声 | 用户截图选择立体声混音，原默认系统输入可能指向它。这是可观察线索，未访问用户录音来确证。新增授权后自动优先麦克风、实际输入名称、实时电平、低于 −60 dBFS 提示。显式选择保留，缺失音轨拒绝录制；不会增益补偿或改变样本来掩盖低信号。 |
| 感觉只能保存候选 JSON | 原本地保存通道已有 MP4/WAV，但已保存后 dirty=false 导致按钮禁用，候选文件又未同名关联。保存按钮移到采集状态顶部，停止后可直接保存，保存后可另存，增加停止后的直接回放。 |
| 保存唇形必须重新分析 | 导出新增 `audio_recording.lip.json`，同 WAV 自动关联，可直接进入 M02/M12。保留 `candidate.lip.json` 和完整帧记录。文件内保存 `source_backend`、`source_status=candidate`。检测不足两帧/超预算不造可用结果，保留完整记录并提示。 |
| 独立面部模型过小 | 用整段结果预览帧共同包围盒进行固定显示变换，面部居中占宽/高约 82% 上限。相机叠加与科研坐标未改，完整帧回放与缺失留空不变。 |
| 极短录制只留下候选帧 | 发现编码器尚未产出媒体就停止的情况，新增明确失败提示，不能报 ready 或将其称为无声录音。 |

离线分析保留为需要 V2 legacy 模型时的可选步骤，与保存解耦。实时模型的科学等价状态保持 candidate，未偷偷切换算法。详见 [决策](../decisions/ADR-M05-R2-local-recording.md) 和 [计划](../plans/2026-10-03-m05-r2.md)。

## 失败及修正记录

- 新增自动关联测试先在旧代码上复现缺失 `audio_recording.lip.json`，实现后通过。
- 新显示变换测试最初对两次浮点减法作严格相等断言，差为约 5.7e−14 像素。改为按画幅和机器 epsilon 推导的舍入界限，未放宽科研数值断言。
- 首次 Chrome 测试在首个媒体块前停止，揭示无有效媒体的状态误报，产品已加明确错误。后续完整采集检查等待至少一秒并实际核对媒体文件。
- 新 16:9 fixture 起初把人脸缩得过小，legacy 模型未检出。保留失败记录，调整公开测试图的裁剪显示使人脸尺寸适合检测；未修改模型/检测阈值，不将无检测帧填成有效数据。最终测试等待完整帧加载后读取网格。
- Qt offscreen 默认 GPU 出现共享图像 context lost，全面禁用 GPU 又使 MediaPipe WebGL 的 activeTexture 不可用。最终仅对测试进程设置 `--disable-gpu-compositing --disable-gpu-rasterization --mute-audio`，保留模型所需图形上下文并通过验收。仍有共享图像诊断日志，未宣称修复显卡驱动或全设备渲染。未修改产品启动器/系统配置。
- 额外历史导入检查首次误用不含 openpyxl 的 M05 科学环境，12 项失败、6 项通过；切换项目已有 M01 环境后 18 项全部通过。未安装或升级依赖。
