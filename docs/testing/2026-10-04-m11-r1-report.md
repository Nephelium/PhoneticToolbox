# M11-R1：词典与转写选择、速度修复及体积测算

2026-10-04。**Windows 源码限定范围 verified**。井井当前授权要求已落实：词典下拉、共存转写文件的来源选择、新 Beam 默认 100/400、短音频速度核查与优化，以及不执行打包的 MFA 体积测算。依据 [方案](../plans/2026-10-04-m11-r1-design.md)、[ADR](../decisions/ADR-M11-R1.md)与[说明](../manual/mfa.md)。完整 M11 的远程/Linux/发行状态沿用原报告，不扩大为全平台 verified。

## 失败原因与界面

- 旧目录入口和浏览器配对函数均要求每 WAV 只有一份同名转写，LAB 与 TextGrid 同时存在会被拒绝。现在自动模式仍明确提示歧义，显式选择 LAB、TXT、TextGrid 后只读取所选格式，其他文件可保留。预算仅计算实际导入资产；格式缺失不回退。来源更改后阻止提交之前已加载的文件，要求重新读取。
- 选择语料目录递归扫描目录和说话人子目录，导入音频与转写只读取手选文件，两者使用同一资产与任务链。
- 发音词典改为与声学模型等宽下拉框，显示已登记配套词典、当前页面导入词典与导入其他词典入口。声学模型按内容摘要去重，选登记词典绑定对应登记组合，取消文件选择保留原值。自定义词典仅作为任务输入，重开页面需重新导入。
- 新草稿与省略配置的请求默认 Beam=100、Retry=400。显式旧值与历史请求保留。更宽 Beam 可能增加搜索耗时，不能当加速选项。
- 截图所示目录中一份 LAB 使用 dai1、tai2、tai1 等拼音，登记的 mandarin_mfa.dict 收录汉字，故 MFA 返回 OOV。这与目录格式冲突分属两处检查。本机已有 mandarin_pinyin_tab.dict 的音素集又与当前声学模型不匹配，真实原生小任务返回 m11_model_mismatch，不能仅换文件名或忽略发音使其通过。
- 截图 TextGrid 仅含 words/phones。独立转写层仍由 MFA 解析；仅有一个非空 words 层时，任务副本按顺序提取词标签为整段转写重新对齐，原边界不作为约束，phones 不作为词。转换记入 provenance，原始文件保持。多个 words 层无独立转写时拒绝猜选。

原语料仅聚焦只读查看上述截图指定样例，未上传、修改或复制进版本控制。速度与 GUI 验收使用新生成的公开合成输入。没有为解决拼音资源不兼容而改写转写、词典发音或声学模型。

## 速度与 CPU/GPU

旧 child 设置 USE_MP=False，但 MFA 3.3.8 的 run_kaldi_function 在此分支仍启动 Worker。USE_THREADING 默认 False 导致 Windows 各阶段启动新 Python，日志多处约 5 秒。启用 MFA 原生线程工作模式，保持一 CPU 作业、单 BLAS 线程，移除被 PretrainedAligner 忽略的配置参数。运行环境仍对所有代码、原生库和数据逐文件计算 SHA-256，4 线程按 64 文件批次并行读取，原排序组合摘要保持完全一致，无元数据缓存或跳过文件。

MFA 原生 normalize_text 后立即检查被排除发音及 save_oovs_found，错误先于词典图编译和 MFCC。具体 OOV 写入本机日志，页面的公共失败提示仍不包含语料内容。编译库函数缓存按完整环境内容指纹隔离，只复用 Numba 库函数，不共享音频、转写、模型、词典、SQLite 或 MFA 状态；缓存与任务共同计入原 512,000,000 B 临时空间软监测。

同一主机、2.8 秒公开合成输入、完整普通话词典、相同 Beam 100/400 的实测如下。外部阶段包含 Python 启动、MFA 初始化和结果回读，不含前面的环境指纹与输入准备。

| 场景 | 外部阶段秒 | 备注 |
| --- | ---: | --- |
| 改动前 | 80.116 | 实际成功任务 |
| 线程模式，独占任务缓存 | 50.156 | 同一输入与完整词典 |
| 线程模式，共享库函数缓存首次 | 51.541 | 首次编译仍有开销 |
| 同缓存复用 | 45.842 | 比改动前短约 42.8% |
| 完整词典 OOV，提前检查 | 17.682 | 返回具体未知词，未生成 MFCC |

旧串行环境指纹 14.620 秒，新并行一次 8.325 秒，后续缓存测试校验为 9.098/8.723 秒，仍然完整读取全部文件。因此 45.842 秒不可当完整点击到完成时间。外部成功任务峰值 1,752,391,680–1,873,240,064 B，原 2 GiB 进程组预算保留；任务加缓存采样峰值约 439 MB，原软磁盘预算保留。上述为所测输入的单次墙钟样本，不能声称稳定吞吐或自然语料边界准确率。

改动前、线程、缓存首次及复用四份输出逐项比较：TextGrid 词/音素标签、所有时间与 tier 结构完全一致。仍有模型及完整词典每任务初始化开销，多个短文件在同一任务提交可共享一次初始化；未实施常驻 MFA、词典数据库共享或科学资源裁剪。

本机 Kaldi build 为 5.5.1172+cpu_hb4f072a_2，当前普通话模型为 GMM-HMM。此 MFA 3.3.8 对齐链没有 GPU 设备切换，界面明确显示 CPU。没有修改 CUDA 或安装新依赖。依据：[官方 3.3.8 对齐入口](https://montreal-forced-aligner.readthedocs.io/en/v3.3.8/user_guide/workflows/alignment.html)、[官方 Worker 实现](https://github.com/MontrealCorpusTools/Montreal-Forced-Aligner/blob/v3.3.8/montreal_forced_aligner/utils.py)、[搜索参数说明](https://montreal-forced-aligner.readthedocs.io/en/v3.3.8/user_guide/configuration/global.html)。
