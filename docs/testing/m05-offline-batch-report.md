日期：2026-10-13。范围：Windows 当前源码、独立 Chrome、真实本机 API／worker、冻结 FaceMesh 0.10.14、实际 MP4／GIF 编解码。未重打 EXE、未发布。

## 改动与行为

- 顶部模式菜单增加离线分析，操作按钮为选择文件与分析所选文件，原独立离线区移除。支持多文件，单项失败保留诊断并继续，取消停止后续项。
- 每个成功视频自动进入历史结果，显示输入文件名。新任务记录受管源视频引用，重开后可恢复视频和测量；每次只保留一份历史视频 Blob。
- 结果保存位于右侧最上方，默认高清 1080、视频与动画均勾选、多文件保存本批全部成功结果。保存（应用偏移）使用各结果自己的值，保存（不应用偏移）写零人工偏移。整批选择一次目录，各视频独立子目录，完成后才清对应未保存标记。
- 完整保存包括既有科学数据、WAV／时间信息及所选视频与 MP4 网格动画。单独导出动画 MP4／GIF 只向选择目录新增该动画，不重新识别或创建分析任务。
- MP4 与 GIF 直接复用已分析完整帧，使用相同面部范围、冻结完整网格、30 fps 显示采样与音频覆盖范围，GIF 无音轨。GIF 使用白底到网格线的专用 256 色抗锯齿调色板。
- 网格表来自既有 resources/m05/metric-spec.json，逐边核对与冻结 MediaPipe 的无向 tessellation／contours 完全一致。编码不再为读取连接表导入模型，保留原 1 GiB 子进程内存上限。
- 单独动画的预算只计算本次新增输出，完整结果计算当前独立结果目录，不把用户目录已有文件计入保存预算。

## 2026-10-18：离线同步回放与统计

本轮仅修改当前源码及生成的开发阅读/前端资源。旧 EXE 和线上应用未替换。原编码无法在 Qt 解码时，原实现直接进入独立动画时钟，造成无画面、无声音却有唇形动画。部分 MKV 还能只加载音轨而不触发 media error，故同时检查画面元数据，音轨在可观测解码计数存在时检查实际解码。

桌面在受管源引用上建立有界临时回放任务，独立 M05 环境将其转换为 VP8/Opus WebM，保留所有视频帧、不等间隔 PTS 和音视频相对起点。转码后核对帧数、毫秒容器精度内的帧时间、音频起点/时长，分块读回校验 SHA 后释放原生暂存。页面使用返回的原时间原点与正式音频 anchor 映射回放和人工偏移。仅用于播放，视频保存仍为 MP4，输入接受 MP4/AVI/MKV/MOV/WMV/M4V/WebM。没有原视频引用的旧历史限制保持。

四模式按预览、实时计算、视频录制、离线分析排序并更名，模式内部身份和科研处理方式不变。采集统计在离线模式继续显示本页上次采集，当前正式结果另列离线解码/推理/检出/缺失；统计说明可展开。正式说明书正文、模块 README 与开发说明同步；静态配图已按同日补充更新，原真人录屏保留。

### 同日补充：未授权音频设备列表与三端流程

用户继续反馈列表只有自动选择与未授权麦克风。录音页使用原生WASAPI枚举，唇形页使用浏览器媒体接口；预览请求 `audio:false`，允许摄像头后仍未获得麦克风设备名称。只解除选择框禁用不能解决这个状态。

Windows、macOS和网页共用 `devices.ts` 与唇形页面。首次点击授权并刷新设备时，桌面桥明确按devices用途准备权限，仅请求 `getUserMedia({audio:true,video:false})`，在临时音轨仍有效时重新枚举，再在finally立即停止所有音轨。页面初次打开、模式切换及已有具名列表的普通刷新均不打开音频。列表不再把匿名隐私占位作为可选麦克风，保留浏览器真实ID、所有具名音频输入及原选择。读取期间锁定开始、模式及设备选择，沿用与录音模块的占用保护；卸载或读取失败后释放临时音轨。Qt按音频设备用途显示权限说明，只允许音频权限，拒绝后可重新授权，不允许该用途请求摄像头。

Qt原生拒绝本次音频权限时，媒体接口实际返回 `AbortError: Invalid state`。设备读取现通过已有桌面权限回执转换成明确的麦克风授权提示，其他读取中断也提供重试入口。不会显示原始Invalid state。此前错误提示、测试固定NotAllowedError的假设均已按实际Qt回执修正。
