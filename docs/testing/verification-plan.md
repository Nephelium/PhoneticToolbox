# 验证与科研回归策略

D0.3。以下是计划，除本次文档/基线/来源检查外，不表示已经运行。

## 1. 三种基准分别保存
- 产品基准：井井平时使用的 v2.2.0.exe；文件 SHA-256 已登记。
- 源码基准：v3 baseline commit 及文件 SHA-256；与 exe 文件一致性不是同一个问题。
- 数值基准：指定输入 + 参数 + 后端/环境版本下独立捕获的 v2/上游/解析预期，P03 才生成。

用户给出的目录里已发现 928 个 WAV、857 个 TextGrid、45 个 XLSX（其他 CSV 等亦存在）；当前仅读取 17 个 WAV 文件头，其中 12 个有同名候选配套文件。配套文件是否来自当前配置尚未验证，不能直接当 golden。
这些原始文件只读、不上传、不提交。绝对路径样例清单在忽略的 docs/baseline/local-evidence.json。
不用井井再次准备整套数据；由 P03 选择持续元音、嘎裂声、EGG、普通标注、短音频和长音频，并记录来源与是否可公开。

## 3. 数值误差规则
- 先固定版本和参数，再比较。数组 shape、时间数组、有声/缺失 mask、单位、参数键必须一致。
- 相同代码/环境的纯数组迁移，默认 rtol=1e-7、atol=1e-10 为起始阈值；不适用的量分别在 manifest 定义。
- WAV PCM 16 量化最多 1 LSB 差异作为初始标准；浮点输出与随机生成另有精度/seed 规则。
- REAPER/Praat/VTL 原生跨平台差异先测量再设定有科学理由的参数级容差，禁止给所有参数统一一个巨大容差。
- 边界不“容差化”：选区、TextGrid、帧数、输出文件数量、音频时长、参数选择和排序要求语义正确。
- 若发现 v2 算法缺陷，建独立缺陷/ADR：先描述差异，获得算法修正授权，再更新预期。不能靠复制缺陷声称科学正确，也不能借 UI 重构暗改结果。

## 5. 科学重点
Jitter/Shimmer：WM-PC 周期检测、IRAPT/实际回退记录、local/RAP/PPQ/APQ 变体不能混淆。
CPP/HNR：窗、倒谱方法、频带、缺失值与 v2 一致，不能把方法同名当数值等价。
校正：Iseli 2004 等实际公式和旧文档误年分开修订；先不改计算。
发声：帧长/步长是 samples；源/目标方向、步数、三类与六组输出、随机参数、端点、manifest/取消。
TextGrid/唇形：时间起点与共享 lip_manual_offset；保存标注与保存偏移分开。
感知：刺激预加载、客户端计时、后台标签处理；网络响应时间不得成为刺激时序。
声道：来源几何/显示变换/计算管道区分；真实音频输出和声卡回调测量，不能只画会动的图。

## 7. 10 用户场景与性能
在 WSL 独立环境准备 10 个测试账号；每人上传不同样例、排队处理、查看进度、下载、清理。
分别记录 10 人轻交互、2 重任务+8 人交互、10 人同时提交批次、单人触顶、到期清理与 worker 崩溃。
记录 CPU/内存/磁盘/带宽、API p50/p95/p99、任务等待/执行、磁盘峰值/预留、错误率与公平性。
初始目标：轻量 API p95≤500ms、典型交互反馈≤100ms；计算任务不套用 API 时延目标。数据量与硬件写入报告。
若未达目标先定位/调队列与视图降采样，再做有依据的服务器规格建议。没有实测前不保证某款阿里云实例够用。

## 8. 发布准入
每个发行物必须有版本、平台/架构、核心与前端 hash、依赖/原生版本、来源许可清单、构建命令、测试报告。
Windows：单文件与安装版分别验证，干净账户/无 Python/无 Node、离线、非项目 cwd、Unicode 路径、更新卸载数据保留。
Mac：实际构建与启动，Apple Silicon/Intel 分开；签名/公证按实际发行方式验证；无实机暂列未验证。
Linux：目标发行版 glibc/图形栈/音频设备，AppImage 或安装包分别测试；WSL 服务通过不是桌面通过。
服务器：登录隔离/配额/TTL/恢复/日志/健康检查/升级回滚；生产部署前单独确认。
任何一项未测写未测，不能用“理论跨平台”覆盖失败。
