# P19 每次启动反馈与非首次启动提速

2026-10-08。井井要求改善免安装 EXE 的再次启动，并明确所有普通启动都显示进度条。状态：限定 Windows 本机源码、实际原生卡片、Qt 与最终成品 verified。只交付本地免安装 EXE，没有公开发布。

## 诊断与改动

井井给出的 Manual-20261007-R3 已在昨晚构建并由说明书任务交付，它已经包含持久缓存。随后 M18-R2 的批注等改动当时仅更新源码。本轮使用当前统一冻结输入，包含冻结时已有的 M18-R2 源码和阅读资源，不回写正式作者工程。

最初现场进程记录显示外层 EXE 至内部应用创建相隔约 28.42 秒；当时启动记录为 science/host/apps 全部复用，缓存检查约 7.38 秒。独立调用同一旧成品准备入口耗时 8.077 秒，内部检查 7.328 秒，仍全部复用。可以确认再次启动仍需打开、检查数以万计文件，没有重新展开整套大组件。原等待中额外约 21 秒的来源未确认，不能直接归因于杀毒软件。之后同条件对照未稳定复现那次长延迟。

- 公共启动卡片在普通引导入口一开始显示，首次、再次、升级和修复都能看到。可计数的准备与校验显示真实百分比；Qt 主界面初始化时使用活动进度条，等待超过 30 秒更新提示，不伪造百分比。
- 每次启动建立专属 Windows 事件。Qt 在首页、字体及两次网页动画帧就绪后通知关闭卡片；重载或关闭会使迟到回调失效。命令行验收、计算工作进程和更新辅助进程保留原有分流。
- 每次仍校验全部实际文件内容及路径。四个读取线程重叠文件打开等待，同一次操作内相同硬链接只读取一次。没有跨启动跳过散列检查；长度及修改时间不变的内容损坏仍能检测。读者全部结束后才进入失败修复。
- 启动记录增加各组件用时。统一构建入口的 `--compact-onefile` 自动启用持久启动器，本次构建有意省略历史 `--persistent-cache` 参数，成品身份和行为均验证通过。以后通过此入口打包，自动继承进度条及优化；已有旧 EXE 需换用新文件。

实现涉及 `desktop/src/ptb_desktop/startup_cache.py`、`startup_progress.py`、`startup_ready.py`、`startup_presentation.py`、`host.py` 及 `scripts/cache_launcher_entry.py`、`build_v3_local_preview.py`。长期要求记录在[打包规则](../../release/PACKAGING_RULES.md)，设计见[计划](../plans/2026-10-08-startup-feedback-design.md)。

## 失败记录、清理及边界

初次卡片源码测试引用了不存在的图标路径，改用已有真实图标后复验；没有改变产品断言。首次成品卡片截图被 DPI 不感知的 QA 监视器裁切，监视器切换正确线程 DPI 后重做完整截图并核查。第一次两种更新 QA 的旧文件目录缺少 `application.json`，明确失败；补齐来自旧成品真实字节身份的描述后，使用新的隔离目录重验，两种实际换版通过。早期失败输出保留，未放宽安全校验。
