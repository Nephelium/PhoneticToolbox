# 试听自动增益、实验音量与折叠侧栏

日期：2026-10-22。实现与验证对象为当前共用源码、本机工作台构建和本机网页候选。

## 功能与数据边界

设置 → 音频新增默认开启的音频音量自动增益。桌面保存在原本机偏好，网页通过 APP 账号偏好保存；开关状态不写入音频文件。共用播放节点立即跟随开关，M10 改开关时停止旧试听，下次播放采用新值；M16 在下一次试听请求中采用新值。

已解码 PCM 按峰值计算固定线性增益，目标 -1 dBFS，最大 32 倍，峰值不超过 1e-5 的静音不放大。先计算增益，再保留用户音量滑条。M10 在原试听变换与包络之外应用播放增益，实时流按已生成的峰值保守限制；M16 不超过 800 万帧的选区先读峰值，超长流按已读取峰值限制，避免首次试听扫描无限文件。

| 播放入口 | 接入位置 |
| --- | --- |
| 分析、合成、变速变调、语谱图重建、TextGrid 等共用选区播放 | `state/audio.ts`，不修改源数组、选区时长或进度规则 |
| 说明书、IPA 示例、唇形回放、感知实验素材预览 | `state/media-audition.ts`，在原生媒体输出图上应用增益，保留原控制器与时间轴 |
| 录音模块 | 浏览器 AudioContext 与本机设备输出均接入播放端增益，原始采集不变 |
| 生理参数合成 | 本机 LiveAudio 与浏览器 BrowserAudio 共用 Python 增益规则，Wasm 源码包和摘要同步 |
| 正式感知实验 | 不读取全局试听开关，只读取实验配置 `playbackVolume` |

原生媒体附加解码受 64 MB/600 秒预算限制，跨源资源、资源不可读或格式不能附加解码时保留原始音量并在当前播放器显示提示。关闭、卸载和新请求取消迟到读取，不上传研究音频。视频是否有可解码音轨由浏览器支持情况决定。本轮没有把长视频/不支持编码的回退标为已增益。

感知实验由实验者在参数页调整 0–100% 的实验播放音量，默认 100%。正式刺激、提示音和预检试音使用该值，素材预览仍使用全局试听。旧项目和旧会话缺省为 100%。项目 JSON、账号偏好与会话快照保留音量，CSV/XLSX 结果末尾追加 `Playback_Volume`，原有列位置保持。采集、科研计算和合成/视频导出不应用试听自动增益。

折叠侧栏为滚动条保留对称空间，顶部应用图标采用居中网格。导航图标、展开按钮和底部图标共用栏中线，展开后的侧栏布局沿用原设置。

## 实际验证

- `npm test`：654 项通过。后续补充试音与结果音量字段后，33 项 M15 以及此前 64 项音频/M15/阅读器定向检查通过，未降低原断言或容差。
- `scripts/verify_audio_gain.py --python`：63 项通过，覆盖 M10 开关两种状态、Windows WASAPI/ALSA 输出形状及采样时钟、M16 录音/差分试听/原始数据/导出回归。实际设备使用测试输出 stub，不宣称物理声卡通过。
- `backend/tests/test_perception_preferences.py`：7 项通过，验证全局布尔开关、独立实验音量范围与研究数据不进入偏好服务。
- typecheck、contracts:check、ui-data:check、build:workbench 通过。架构检查零错误。
- `scripts/verify_audio_gain.py`：独立 Chrome 七组通过。实际共用 AudioContext 的低电平输入获得增益、播放中关闭立即恢复、音量滑条有效、完整刷新记住关闭状态；真实 ManualMedia 合成 WAV 播放应用增益；正式实验实际 GainNode 只采用实验音量；三种缩放下逐个量取折叠图标位置，距中线均小于 1 个物理像素。
- 同一隔离测试实际载入 Qt WebEngine，共用页面开关、AudioContext 增益与关闭、浅深主题和折叠图标居中通过。使用独立 Qt 缓存/配置目录，offscreen/静音模式，不替代实体设备听感或最终桌面宿主的完整媒体组合验收。GLES3 回退日志保留。
- `scripts/verify_m10_wasm.py ... --audio-gain`：实际 Chrome/Wasm 三组通过，界面全局开关经父页桥接到 Worker。相同测试音峰值关闭约 0.100381，开启约 0.714667；音量从 0.8 调至 0.4 后峰值约 0.358452。切换试听增益前后的动作导出 PCM base64 完全相等，执行身份确认为 browser-wasm。
