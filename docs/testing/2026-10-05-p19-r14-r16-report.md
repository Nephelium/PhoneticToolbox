## 首次最大化的证据与边界

井井报告冷启动第一次最大化有几秒黑屏。定向基线观察没有稳定复现相同现象，因此无法确认唯一根因，也不声称已证明所有驱动及 DWM 情况消失。基线 Qt Quick 背景色已经不透明，未把透明背景当作已证实根因。

新增 `desktop/src/ptb_desktop/presentation.py`，接入实际 QQuickWidget 的 QQuickWindow `afterFrameEnd` 回调。Qt 文档说明 QQuickWidget 使用离屏渲染目标，普通控件可覆盖其上；该信号支持 QQuickRenderControl。这里确认的是渲染帧已提交，不是显示器硬件完成扫描。没有调用子控件 `winId()`、重载页面、重置 WebGL、强制关闭 GPU 或修改系统设置。依据：[QQuickWidget](https://doc.qt.io/qt-6.11/qquickwidget.html)、[QQuickWindow.afterFrameEnd](https://doc.qt.io/qt-6.11/qquickwindow.html#afterFrameEnd)。

成品两次独立冷启动分别在窗口刚显示和文档就绪后发送原生最大化命令，每次再还原、第二次最大化。首次覆盖层约 547 ms / 16 ms 后撤下，两次均只出现一次。页面 token、渲染进程与 WebGL 上下文保持，没有渲染终止。窗口动画开始的 300 ms 不作为桌面截图黑屏判断；之后先确认四角及中心归属于本任务窗口，再采集本窗口区域，未检测到整幅黑画面。

早期未确认窗口归属的基线抓图不计入验证。测试使用独立工作区、数据库、浏览器 profile 与专用窗口标题；置顶标志仅在验证入口启用。未操作井井已有窗口或状态，未测系统真实鼠标点击、全部显示驱动、实体 DPI 切换及长时间运行。
