# M16-R4 录音设备、Praat 显示与侧栏修订

2026-10-04。状态：verified，限定 Windows 开发态、只读本机设备枚举、合成采集/播放与 WSL 纯核心。实体设备录制、热插拔、DPI 与 Linux 原生录音未验。本轮未打 EXE。

## 交付行为

1. Windows 设备列表仅保留 WASAPI 当前启用、默认格式查询通过的端点，移除重复 API 别名和旧驱动入口。实机只读查询由 40 个入口缩减为 4 个，分别为 2 个输入、2 个输出；系统启用的立体声混音保留。不按名字去重，因此同名的不同实体不会被误合并。设备身份和原生索引不重编号，选项失效后清空并要求重选，采集中禁止刷新。
2. 默认波形仅显示左声道，显示语谱图右侧新增显示所有声道。所有波形均分可用图高，去掉内部纵向滚动条。采集通道、剪辑同步、降噪勾选与 WAV 导出不随此开关改变。语谱维持按试听与语谱声道选择单个声道。
3. 语谱实际使用已安装的 Parselmouth 0.4.7 / Praat 6.1.38，Gaussian 5 ms、50 dB 相对灰度、6 dB/oct 显示预加重、0–5000 Hz，与公共语谱复用灰度函数。标记 `m16-praat-display/1`，保留原始录音与降噪算法。旧 Hann 显示纯核心与原断言保留，录音页接入新的有界 Praat 显示。
4. 状态提示（含已导出数量）与导出结果移至左侧栏，长文件名换行并有界滚动。导入表格改为导入任务，保存清单模板改为保存任务模板并附用途说明。所有录音页用户可见 take 文案改为录音条目/录音，内部数据键名保持兼容。
5. 侧栏折叠说明与手册明确任务 JSON 可往返，不包含音频；工程 `.f32`、派生文件、清单和恢复记录的用途，以及 WAV 导出路径。没有迁移现有工程。

## 方法与限制

显示仍按完整可见时间范围取中心窗，实时最多 128、录后最多 640 列。每个 Gaussian 5 ms 窗实际支持约 10 ms，边界补零，流式读取跨工程块/剪辑边界。96 kHz 下最多 640×962×4 字节窗口缓存，11 秒/48 kHz 合成数据初测一次显示计算约 18 ms，不能推断所有机器实时性能。长范围可遗漏短事件，应放大选区。灰度是当前时间范围的相对显示，未经声压级校准，也不宣称逐像素复制 Praat 编辑器。

来源登记给 `SRC-PRAAT` 增加 M16 和实际版本/路径，软件引用由登记重新生成。[PortAudio 官方 WASAPI 实现](https://github.com/PortAudio/portaudio/blob/v19.7.0/src/hostapi/wasapi/pa_win_wasapi.c)使用启用状态枚举，设备格式检查通过既有 sounddevice。未新增第三方库。

底层 PortAudio 可能缓存设备清单；实体热插拔尚未验证，接入新设备后若刷新未显示，可在停止采集后重启工作台。不通过全局重新初始化音频库干扰其他拥有者的流。本轮只读设备查询确认当前启动时的列表，没有声卡实录/听感验收。WAV 导出与工程恢复的功能证据使用隔离合成数据，不读取截图所示工程或博士论文目录。

Chrome 首轮布局断言要求先前导出结果仍存在，但中间增益任务已清掉该结果，最终在布局检查前重新执行真实导出。第二轮八声道测试夹具动态导入了另一份 Vue 实例，导致 ref 不更新，最终改由 Vite 模块统一导入同一 Vue；产品代码未为此绕过检查。两次失败记录分别保留于 `chrome-5079b2a00a18446591557d62c41d2315`、`chrome-ba0c4af7f090484581892e6c31690b40`。Qt 保留离屏 GPU 回退日志，不视作实体 GPU 验收。

本轮未执行 EXE 构建、DDL、push、公开发布、环境安装、删除用户文件或改写旧工程。保留同期 P19/M03 与原图标删除差异，未将这些变更计为 M16 交付。
