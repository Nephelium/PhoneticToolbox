# P19-R18 首次最大化黑屏修复

2026-10-06。井井报告应用冷启动后的第一次最大化仍长时间黑屏，拖动边界正常，授权修复。本轮源码及新单文件 EXE 的 Windows 定向验收 verified。该状态限定以下实际检查，不能外推全部驱动、实体电脑或全部科研任务。

## 定位与改动

旧版在 `WindowStateChange` 中抓取 WebEngine 当前画面。实际 Windows 原生命令时序记录证明，`WM_SYSCOMMAND/SC_MAXIMIZE` 到达后，WebEngine 已从 1440×900 扩为 1707×996，随后才进入状态变更并显示遮罩。基线此次没有稳定复现井井报告的数秒整屏黑，不能将这些时序缺口写成所有驱动情况下的唯一根因。

本轮将保护提前到最大化命令处理前，`WM_SIZE/SIZE_MAXIMIZED` 补充没有系统命令的 OS 路径，`showMaximized` 补充程序调用。仅在原尺寸抓取一次已有工作台画面，扩容后不再通过 `view.grab()` 抓图。页面尚未绘制时使用不透明主题底色和打开提示。

撤下条件改为当前逻辑尺寸与网页视口匹配、Chromium 连续两次动画帧完成、Qt 两次取得尺寸正确且有效的帧缓冲图片。原生覆盖可能抑制下方 Quick 控件的普通绘制，因此不再依靠 `update()/afterFrameEnd` 计数等候。每次尺寸改变建立新的等待代次，迟到的旧回调不会撤下当前保护。还原或最小化取消等待，未完成的首次尝试重新设防。超时显示可还原重试的提示，不把六秒到期当成已出现有效画面的证据。

没有重载页面或重置 WebGL，没有修改科学计算、前端交互、系统 GPU 配置或禁用硬件加速。Qt API 依据：[QQuickWidget 帧缓冲与叠放说明](https://doc.qt.io/qt-6.11/qquickwidget.html#grabFramebuffer)、[QWebEnginePage JavaScript](https://doc.qt.io/qt-6.11/qwebenginepage.html#runJavaScript)。覆盖期间帧缓冲读取的实际行为由本轮真实 Qt 验证确认。
