## 本轮修改

- 手动拖动舌面和舌叶时，原生目标曲线按物理弧长作局部加权平滑，保留材料站位及两端位置，再执行口底、硬腭、牙齿约束，之后计算截面、声管和声学。几何方法升至 `m10/r21`。显示线采用圆角连接，避免描边自身放大尖角。
- 平滑核支持半径为 0.4 cm、9 点采样，属于几何正则化。没有新增人体测量或组织力学依据。旧参数顺序和拖动范围保持，几何结果会变化，交换文档保留版本提示。
- 分享页列出当前模型的自存和内置构型。同音标优先自存，初始选中自存项，显示来源和数量。全选、全不选、刷新并选择自己的构型、子集导出接入实际数据。内置构型包含完整参数和声源。
- 全局调整和超音段特征均提供 jitter/shimmer，支持固定值、相对偏移、时间或关键帧范围、重叠组合及 0–100 限幅。单位为声源调节强度，不能当作分析测得的百分比。沿用序列种子，区段变更不重新播种，取消和异常后恢复原声源设置。
- 三端复用同一页面、Python 核心及 C++ 补丁。Windows DLL 与 Wasm 候选已重建。Mac 构建入口已接入 R21，资源中的旧 Mac 原生库仍为上一版，必须重建后才能运行这版源码。

## 代码审查：需要继续修改的项目

以下保留2026-10-18审查时的发现与建议。五项问题已在2026-10-19后续任务实施，逐项整改、验证范围与多套构型行为见[后续验收](m10-preset-libraries.md)。下方旧行号与尚未实施描述属于当时快照。

### P1：网页自存构型尚无跨标签页长期保存

位置：`frontend/src/platform/vocal.ts:69–71`，`frontend/src/platform/vocal.ts:154–164`。构型、关键帧和常用项写入 sessionStorage，原生计算端使用 MemoryProfile。刷新当前标签页可恢复，关闭标签页后不能依赖该存储恢复。账号偏好保存当前姿势与声源设置，不包含完整构型库。因此本轮刷新选择按钮只能取回当前会话实际存在的记录。

建议：把用户明确保存的构型和关键帧放入按账号、项目、说话人隔离的持久存储；临时计算缓存继续独立清理。读取旧 sessionStorage 时仅在目标未有较新记录的情况下提供接续路径，解析失败应保留原始数据并提示可恢复操作。写成功后再显示已保存。

验收：保存两项并关闭原标签页，新标签页恢复；两账号、两项目、男女模型互不串库；旧缓存和新记录冲突时不覆盖较新数据；明确清除和退出账号后的数据边界可复核。

### P1：一次配额失败会让后续保存永久失败

位置：`frontend/src/platform/vocal.ts:155–164`。`savedQueue=savedQueue.then(...)` 没有在下一次写入前恢复已拒绝的 Promise。首个 sessionStorage.setItem 抛异常后，即使腾出空间，下一次保存也不会执行 setItem。

已用实际 webVocalPort 的受控存储故障复现：第一次写入抛配额异常，随后解除故障并再存，写入次数仍为 1，两次操作均报空间不足。脚本为 `output/validation/m10-smoothing-20261018/review-quota.mjs`。

建议：下一次任务从捕获旧异常后的队列继续，每次任务独立返回其失败；先构造待保存快照，落盘成功后再提交内存 profile。不要通过吞掉当前错误显示成功。保存失败时保留导出入口。

验收：首次失败、第二次成功；连续快速写入顺序保持；切换模型或关闭工作区不会把未落盘结果当作成功记录。

### P2：保存名称规则与构型包导出规则不一致

位置：`frontend/public/vocal-tract/presets.js:8–12`、`desktop/src/ptb_desktop/vocal_tract/profile.py:63–78`、`packages/phonetic_core/src/phonetic_core/vocal_tract/preset_pack.py:24–31`。保存允许内部空格，例如 a i，导出时却拒绝包含空白的音标。用户可以得到可载入但无法分享的构型。不同 ID 的记录也可能具有相同规范化音标，包校验再拒绝重复。

建议：明确区分显示名称和 IPA 匹配键，或统一新建时的名称规则；导出前列出具体冲突项，允许用户更名或取消勾选。既有自定义名称应保留，不能批量静默改写。

验收：内部空格、组合附加符、方括号/斜线名称、规范化后同名构型均能得到明确且可恢复的结果；合法名称保存、选择、导出、导入一致。

### P2：旧构型包缺少明确的重算导入路径

位置：`packages/phonetic_core/src/phonetic_core/vocal_tract/preset_pack.py:18`。包要求 geometry_method 与当前引擎完全一致。R20 包在 R21 被拒绝，即使参数顺序和说话人摘要相同。序列文档已有旧版本读取并提示重算的机制，构型包没有对应入口。

建议：保留严格版本校验，另外设计明确的旧参数包预览与重算流程。先显示来源版本、模型、参数范围和冲突项，再由用户选择导入；写出新包时记录当前几何方法及来源。几何变化后不能承诺旧音频逐样本复现。

验收：R20→R21可预览重算，模型/摘要/参数顺序不匹配仍拒绝；取消不写库；覆盖与保留规则一致。此项涉及兼容性政策，本轮仅提出方案。

### P2：桌面旧目录的构型读取与关键帧读取不一致

位置：`desktop/src/ptb_desktop/vocal_tract/profile.py:36–39` 与 `:80–87`。未找到当前关键帧文件时会尝试 legacy 目录，构型读取只检查当前目录。设置了 legacy_directory 且用户旧构型仍在旧目录时，会显示空构型库。这是明确的分支差异，尚未证明井井截图就是这个原因。

建议：先读取并展示旧构型是否可用，采用与关键帧一致的来源优先级。新目录已有数据时禁止自动覆盖；如需迁移，单列来源、数量及冲突并按项目授权规则执行。

验收：仅旧目录有数据、新旧均有数据、旧文件损坏、女性独立目录四类夹具；确认读取不会修改旧文件。

## 几何与性能的后续建议

1. 增加两模型的手动组合验收矩阵。舌面、舌叶、舌尖、下颌及口底共同变化时，分别量化最大转角、轮廓自交、硬组织侵入量和面积随拖动的连续性。当前单个尖角回归与既有原生测试不足以替代完整空间检查。
2. 评估高曲率区域的自适应表面采样。当前固定材料站位有助于稳定拖动，但有限网格仍可能把连续曲线显示为折线。应把几何采样与显示细分分别量化，维持显示、截面积分和合成的一致来源。
3. 对 `animation.py` 的采样路径做剖析，再缓存时间节点与区段事件。当前每个音频块和画面会重复插值、复制及遍历特征。优化应以同种子 PCM、关键帧边界和几何数值等价为验收标准，保留取消响应和资源上限。
4. 将名称、版本与模型隔离校验集中为共享数据契约。前端用于及时提示，核心负责最终校验，桌面和网页的存储适配器只执行读写，减少同一构型在不同入口得到不同结果。
