## 实现

- 设置页改为等宽双栏，字体分为界面、图表与导出、预览，标题与控件对齐，窄窗按单栏显示。
- 五个字体选择框共用原生 `select`，与代码字体菜单形式一致。始终显示完整列表，读取本机字体后并入候选，保留当前自定义值、系统默认和自定义输入入口。
- `fonts.v1` 增加可选 `bodySize`，默认 14 px，整数 10–24。历史值缺省时补默认，已有字体与图表字号保留。预览与应用分开，正文和图表字号分别保存。
- CSS 字号改为以正文基准计算的 rem；没有调整绘图数据或像素尺寸。主模块、M10 独立页面、参数估计文件名均接入基准。导航与标签同为 1 rem，辅助文字与标题保留相对层次。
- 搜索框和收起按钮同行，输入框宽度随 184–360 px 侧栏变化；收起后保留展开入口。
- M08 用时间/音高图标，M09 用谱图/声音图标，M11 用强制对齐图标，M12 用分层区间格。17 个模块的图标键全部不同，首页、侧栏共用映射。
- M10 的声学曲线、横截面、F0、实时谱图和参数控件使用主题语义色；滑块与参数输出使用强调色，实时谱图从面板色渐变到强调色。组织模型的 `scene.js` 与模型资源未改，原有浅深模式的组织色与选择轮廓适配保留。

## 全屏黑屏的证据与边界

用户截图显示标题栏和滚动条仍在，网页内容整幅黑屏后恢复。截图不足以确定唯一根因，窗口尺寸变化时的 Qt WebEngine/Windows 合成呈现问题属于合理推断，未认定为显卡故障。

旧前端构建在 Windows 原生 Qt 隐藏窗口中，16 次最大化/还原和 64 个截图采样没有复现整幅黑屏。新宿主显式使用不透明网页及窗口底色，按主题同步；尺寸和窗口状态变化后请求重绘 Chromium 子表面与原生窗口，并在 80 ms 后合并一次重绘。保留原渲染进程、页面、选区与科学任务，没有刷新页面或调整系统 GPU 设置。

Qt 的 [backgroundColor 文档](https://doc.qt.io/qt-6/qwebenginepage.html#backgroundColor-prop)说明该底色位于文档后方，可用于减少加载时底色闪烁；[渲染说明](https://doc.qt.io/qt-6.10/qtwebengine-features.html)说明页面最终图像由 Chromium 合成器产生。这些资料支持处理方向，不能证明用户黑屏的唯一原因。实体屏幕、Windows DWM、标题栏双击与实际 DPI 仍需试用确认，因此黑屏仅记录为缓解处理，不能标为已经完全修复。
