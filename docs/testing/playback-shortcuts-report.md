# 音频选区的空格播放修复

任务 `P04-SELECTION-SPACE`，2026-10-10，状态 `verified`。验证范围为 Windows 前端源码、独立 Chrome 和真实 WebAudio 调度。现有冻结 EXE 未重建，Qt 与实体声音输出未重验。

## 问题与修复

M01 参数估计的 TextGrid 片段使用按钮表示。点击后选区正确，但焦点停留在按钮上，公共播放器把所有按钮都排除在空格快捷键之外。浏览器随后执行按钮的原生空格点击，只重新选择该片段。修复前在实际 M01、M04 LPC 页面分别复现了这个问题，手动点击播放按钮能播放同一区间。

M02 参数图表拖选会阻止默认指针行为，却没有主动接收焦点。如果此前焦点在保存等按钮上，拖选完成后空格仍无法播放。此路径同样在实际页面复现。

改动如下：

- TextGrid 片段、明确的音频选择/试听入口及播放器的全部选区按钮使用 `data-audio-selection`。公共快捷键只对这些入口放行，其他按钮保留原生键盘行为。
- TextGrid 点击同步登记音频选区归属，使多音频页面的空格只响应当前选区。
- M02 参数图表可接收焦点，并在拖选时主动接收焦点。
- M07 合成结果试听按钮允许空格停止和再次播放，避免空格反复执行结果读取与重播。
- M08 原音、合成音和历史版本试听同步播放器目标，空格可停止当前直接试听，保留原有当前视野/整段试听范围。
- 带音频的结果弹窗允许弹窗内播放器响应空格，背景播放器继续受抑制。此路径用于 EGG 逆滤波结果。输入框、滑块、下拉框、普通按钮、链接、折叠标题、输入法组合、修饰键和未激活模块继续保留自身操作。

没有修改科研算法、采样率、声道、TextGrid 时间边界、合成参数或导出格式。同期主页图标与 M10 改动保留，本任务未提交或推送。
