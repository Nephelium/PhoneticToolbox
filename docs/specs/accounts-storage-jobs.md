# 网页账号、空间和任务规格

2026-10-16 更新的目标政策：网页开放自助注册，研究数据按临时工作区保留，主动点击退出立即启动清理，直接关页/断网/崩溃按最后心跳保留30分钟。每账号1 GB暂作上限，全站容量另行准入。当前 storage_policy.py 仍实现旧policy_version=2/259200秒；新策略尚未实施，实际迁移与部署另验。取舍见[专题决策](../decisions/ADR-web-ephemeral-client-first.md)。

## 1. 身份与归属
研究者账号、会话、临时项目、资源、任务分表/模型管理；owner 由已认证会话确定，不能信任请求体传入 owner_id。
私有资源读取、下载、波形/谱图、任务日志、进度 SSE、取消、归档和删除都检查归属。猜中 UUID 也不能访问。
桌面模式不要求云账号，本机资源通过本地会话访问。
登录采用成熟密码哈希实现（候选 Argon2id）、安全会话 cookie、CSRF 防护、速率限制、退出撤销；密码恢复在正式开放注册前设计，不写管理员通用后门。
一期开放自助注册，邮箱验证后方可使用服务器工作区，提供找回密码。验证/恢复令牌仅存摘要、一次有效且有期限；注册、重发与恢复均限流，响应不泄露账号是否存在，重置后撤销旧会话。邮件供应商/域名配置与真实发信在实施时核定，不调用旧站用户表或反馈系统会话。
账号相关记录与语料分开；说明书明确“账号持续可用”不等于“音频永久保存”。
M15 配置、刺激、计时、存储与导出保持纯客户端，见[M15决策](../decisions/ADR-M15-client.md)。网页启用前补账号/工作区命名空间及退出后的访问隔离，不把计时搬到服务器，也不默认上传实验数据；旧无主记录只允许显式导入。未来服务器实验分发另行设计。

## 2. 额度定义
quota_bytes = 1,000,000,000（十进制 1 GB）。
used_bytes：属于该账号、已落盘并完成记账的输入、结果、编辑文件、图表、下载归档和临时数据。
reserved_bytes：已接受的剩余写入预算，短暂包含已落盘但尚未完成逐块结算的字节；这些字节始终被预留覆盖，不可提前释放。
available_bytes = max(0, quota_bytes - used_bytes - reserved_bytes)。
共享安装模型/字典/程序不计入账号额度，但必须计入服务器整体磁盘容量。不能用全局共享缓存保存私有语料并绕过配额。
逻辑相同文件跨账号默认各自计量；第一版不做跨用户内容去重，以免影响删除、归属和信息泄漏。
数据库中的账号/任务最少元数据不按音频字节计费，但限制条目数量和日志体积。

## 3. 原子额度与写入顺序
1. 鉴权与参数校验，计算保守输出/上传预算；不先接受全部文件到临时盘再检查。
2. 数据库事务锁定用户额度行，以 used + reserved + request <= quota 为条件预留，创建唯一 reservation_id。
3. 受控 writer 按已预留额度写；未知大小流在下一块写入前扩展预留，失败就停止，不得先超写再回滚。每块成功后原子地将相同字节数从 reserved 转为 used，二者不重复计算。磁盘写入和数据库结算之间崩溃时，原 reservation 继续覆盖未结算块，恢复按文件尺寸与块日志核对，不能凭超时直接释放。
4. 临时/最终文件在同文件系统原子 rename 时不双重计费；若复制则同时计入两份直到旧文件删除。
5. 成功后校验真实尺寸、hash、格式，结清剩余未记账字节、提交资产清单，释放未使用余额，再将作业标成功。最终化不能将已逐块记入 used 的字节再加一遍。
6. 异常、取消、断电留下的 reservation 由租约/恢复核对处理；实际仍在的文件继续计 used，不能直接归零。
7. 定期核对磁盘清单与数据库，发现差异冻结新增写入并修复，不把未统计孤儿文件留成隐形占用。

两个请求同时面对最后 100 MB 时，只能在额度允许下一个成功或各预留可分配部分；不能都因为各自读到空闲 100 MB 而成功。

外部工具与旧算法的临时文件也必须受约束。优先通过管道交给受控 writer；必须写目录的 MFA/FFmpeg/原生工具使用能强制总字节上限的作业工作空间（例如经过验证的文件系统项目配额或受限卷），与账户 reservation 联动。只限制单文件大小、定时扫描或生成后再查大小，都不能证明总空间上限。具体机制在服务器原型中验证；缺少可靠限制时不能将该路径标为支持严格配额。只读共享模型不复制成无人计量的私有缓存。

## 4. 满额行为
- 新上传/新生成/新归档被拒绝，返回 quota_exceeded、当前占用、预留、需要空间、可清理建议。
- 已有结果仍可查看、下载、删除；正常登录退出不被满额锁死。
- 用户可不下载直接删除。涉及用户明确删除动作给出文件数量/大小/关联影响，不强制勾选已下载。
- 用户删除进行中，状态 deleting；实际删除完成后才释放占用。失败标 delete_failed，继续占用并提供重试。
- 下载本身不自动删除，不延长寿命，也不当作权限转移。
- 重生成不会覆盖旧批次；需要新预算。不能借重名覆盖逃避保留记录与额度。
- 若批次生成中达到空间上限，默认取消本批并清理未提交临时文件；如保留部分结果，必须显示 incomplete 并计入实际额度，不能伪称全部成功。

## 5. 临时工作区与30分钟断线保留

本节为目标行为，尚未实现。资源与任务除 owner/project 外还须绑定工作区及其有效代数；不能只缩短旧资产TTL。

| 事件 | 服务器行为 |
| --- | --- |
| 登录/进入工作台 | 创建或恢复该账号当前浏览器会话的工作区，注册标签租约；长期账号与临时研究状态分离 |
| 有效心跳 | 建议每30秒一次，保存服务器时间 last_seen；同工作区至少一页有效即保持活跃。普通任务进度、下载或旧链接不能替代用户心跳 |
| 主动退出/结束本次工作 | 立即撤销该会话工作区的读写/发布资格并取消任务，启动幂等物理清理；重新登录创建新工作区，不能恢复已结束代数 |
| 页面隐藏/最小化 | 仅记录可见性，不直接清理；后台节流/休眠导致长期无心跳时按断线处理 |
| 直接关闭页面 | pagehide/keepalive/beacon仅作标签离开的尽力通知，不触发提前清理；与断网/崩溃一样，最后有效心跳后1800秒到期。迟到通知不得误删恢复后的工作区 |
| 刷新/前进后退/关闭部分标签 | 期限内新页面attach恢复原工作区；BFCache恢复须重验租约。其他标签仍存活时不得清理共享工作区，不以慢速刷新触发短延时删除 |
| 关页/断网/崩溃/服务器故障 | 最后有效心跳后1800秒内允许同账号同工作区重新认证恢复，不能因检测到离线立即删除 |
| 到期 | 以服务端时间判断 now >= last_seen + 1800，原子关闭并拒绝后续读写/下载/Range/发布，取消任务、清空研究数据；客户端重新进入空工作区 |
| 服务器重启 | 恢复持久化租约、截止和清理状态，先封锁过期工作区再开放私有访问；不得把last_seen统一重置为启动时间 |

1. 清理覆盖上传、未完成分片、输入、输出、图表、ZIP、编辑副本、缓存、临时项目名、参数/转写、批次/任务历史、事件和结果manifest。纯复制、打包、新生成及仍运行的任务均不能越过工作区关闭/到期；任务发布同时核对owner、工作区状态/代数和worker租约。
2. 清理使用服务器发放的工作区ID及独立存储前缀，不能接受客户端路径或按账号全目录误删其他设备工作区。离线时运行任务仍受原时间/字节预算，在恢复期内可完成，完成不续存；到期后终止并拒绝迟到回传。
3. 正常运行下，目标为工作区因主动退出或到期关闭后60秒内完成受控临时盘的物理清理，实际p95/p99及失败次数单列。立即失效与物理删除分别记录。删除失败进入重试队列，仍有文件的used/reserved不得提前释放；成功后回收对应账本、历史与tombstone。只保留必要清理对象ID到清理结束，不永久保存历史清单。
4. 登录账号、密码摘要、验证状态和必要偏好可持续保存。安全事件只留固定类别、最少身份/时间/计数并设置有限期限，具体期限在上线配置审阅时核定；不得含研究文件名、文本、结果、配置或下载地址，不形成可恢复研究历史。公开论文库/说明书、共享模型与独立反馈会话不属于用户研究工作区。
5. 私有响应使用合适的no-store策略，不进入CDN/Service Worker共享缓存。用户研究数据不进入长期备份、对象版本或调试日志；涉及现有备份/WAL/数据库维护时单独设计可验证清除和恢复流程，恢复不得使已过期数据重新可访问。
6. 用户原文件、已下载结果、桌面项目和浏览器显式保存的本地实验项目不按服务器TTL删除。网页版普通草稿/缓存以会话为界；主动选择的本地持久项目须明确标识、限制账号访问并提供清理入口。退出清空页面引用/对象URL与账号内存状态，不能将A的实验/音标草稿展示给B。不能把浏览器命名空间隔离宣称为抵御设备管理员的加密保护。
7. 清理是上传前可见的产品约定；主动退出提供未下载成果提示与下载入口，但允许用户结束。关闭事件不可靠，界面明确直接关页按30分钟恢复期处理；正常刷新与后台切换不提示已删除。服务故障期间不能执行物理删除时，恢复后先清理并记录延迟。

## 7. 任务调度与计算并发
并发容量以当前目标主机重测为准。10人基线后按25/50/100人交互阶梯寻找边界，不作为承载承诺；旧2 vCPU/约3.4 GiB记录仅供参考。浏览器可完成的操作优先本机执行，服务器未验能力关闭；准入后计算/预览/导出初始合计最多一槽，每人1个运行任务并限制等待队列长度，内存、输出和超时预算按实测冻结。远程节点的资源槽独立配置，详见[节点设计](remote-compute.md)。
API并发连接与计算并发分开。MFA网页线上推理关闭，UI提示下载实际支持平台的桌面版；所有MFA计算入口在后端能力/任务准入拒绝。其他转换/批处理/VTL按操作白名单开放，避免单用户抢满队列。
claim 在短事务内完成，使用 SKIP LOCKED 认领 + lease_generation；执行期间不长时间持有数据库事务。
worker 定时心跳；旧 worker 的结果提交需匹配当前租约代数，避免超时后旧进程覆盖新重试结果。
crash 后任务标 interrupted；只有明确幂等且输入未过期的任务才能安全重试。研究者应能看到重试/失败，不能静默产出两批同名文件。
取消请求先置 cancel_requested，算法检查取消点；外部进程由本 worker 持有并有限时终止。写出完整 manifest 后与取消竞态的优先级在事务中决定。
每批输出独立目录。completed manifest 是完成标记；取消/失败清单保留 incomplete。
原生 VTL 状态按任务或独立会话进程隔离，不共享一个全局 DLL 实例。
实时声道连续发声另作会话能力验证，不占用普通长任务接口假装低时延。

## 9. 新旧政策切换门

统一政策源覆盖额度、工作区生命周期、协议与UI。现有1 GB/3天实现及旧7天manifest是兼容基线，新政策需新版本与增量迁移，不直接改写旧003/006或把旧retention_seconds当作断线计时器。新建工作区只在新协议/数据库/清理器一起通过后启用；现存数据依审阅后的迁移策略保留原期限或提示导出，不按本文自动批量删除。旧客户端不能绕过工作区门，新客户端不能把服务器仍为旧政策的库显示成30分钟已生效。

追加场景：Q21旧账号超额与预留；Q22旧7天/3天manifest回读；Q23 1GB恰好/超1字节；Q24有效心跳后1799/1800/1801秒；Q25账号/全站水位竞态；Q26节点迟到/离线副本；Q27退出与任务完成竞争；Q28刷新、BFCache、后台节流、关闭一个/全部标签；Q29同账号跨设备和A退出B登录；Q30服务器停机超过30分钟再启动；Q31删除失败重试/物理空间回收；Q32关闭请求重放或CSRF伪造；Q33备份恢复不复活已过期数据；Q34注册、邮箱验证、找回、枚举与邮件滥用；Q35未下载退出提示和本地已下载文件保留。Linux、真实PG、Windows/macOS浏览器分别记录。
