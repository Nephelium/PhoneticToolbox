# 网页账号、空间和任务规格

D0.3 / 2026-09-09。这里是实现规格，不表示数据库或服务已建立。用户原话的含义：研究者独立登录；数据最多保存一周；每人最多 5 GB；满了可先下载并清理，也可直接清理后继续。

## 1. 身份与归属
研究者账号、会话、临时项目、资源、任务分表/模型管理；owner 由已认证会话确定，不能信任请求体传入 owner_id。
私有资源读取、下载、波形/谱图、任务日志、进度 SSE、取消、归档和删除都检查归属。猜中 UUID 也不能访问。
桌面模式不要求云账号，本机资源通过本地会话访问。
登录采用成熟密码哈希实现（候选 Argon2id）、安全会话 cookie、CSRF 防护、速率限制、退出撤销；密码恢复在正式开放注册前设计，不写管理员通用后门。
一期可受控创建账号；公网自助注册、邮件验证和发信供应商在部署阶段确认。不会调用旧站用户表。
账号相关记录与语料分开；说明书明确“账号持续可用”不等于“音频永久保存”。
感知实验的研究者需要登录；未来参与者凭受限实验链接作答，权限限于指定实验与匿名响应，不能读取研究者其他项目。公开实验链接作为单独发布动作确认。

## 2. 额度定义
quota_bytes = 5,000,000,000（十进制 5 GB）。
used_bytes：属于该账号、已落盘并完成记账的输入、结果、编辑文件、图表、下载归档和临时数据。
reserved_bytes：已接受的剩余写入预算，短暂包含已落盘但尚未完成逐块结算的字节；这些字节始终被预留覆盖，不可提前释放。
available_bytes = max(0, quota_bytes - used_bytes - reserved_bytes)。
共享安装模型/字典/程序不计入账号额度，但必须计入服务器整体磁盘容量。不能用全局共享缓存保存私有语料并绕过配额。
逻辑相同文件跨账号默认各自计量；第一版不做跨用户内容去重，以免影响删除、归属和信息泄漏。
数据库中的账号/任务最少元数据不按音频字节计费，但限制条目数量和日志体积。

## 3. 原子额度与写入顺序
1. 鉴权与参数校验，计算保守输出/上传预算；不先接受全部文件到临时盘再检查。
2. 数据库事务锁定用户额度行，以 used + reserved + request <= quota 为条件预留，创建唯一 reservation_id。
3. 受控 writer 按已预留额度写；未知大小流在下一块写入前扩展预留，失败就停止，不得先超写再回滚。每块成功后原子地将相同字节数从 reserved 转为 used，二者不重复计算。磁盘写入和数据库结算之间崩溃时，原 reservation 继续覆盖未结算块，恢复按文件尺寸与块日志核对，不能凭超时直接释放。
4. 临时/最终文件在同文件系统原子 rename 时不双重计费；若复制则同时计入两份直到旧文件删除。
5. 成功后校验真实尺寸、hash、格式，结清剩余未记账字节、提交资产清单，释放未使用余额，再将作业标成功。最终化不能将已逐块记入 used 的字节再加一遍。
6. 异常、取消、断电留下的 reservation 由租约/恢复核对处理；实际仍在的文件继续计 used，不能直接归零。
7. 定期核对磁盘清单与数据库，发现差异冻结新增写入并修复，不把未统计孤儿文件留成隐形占用。

两个请求同时面对最后 100 MB 时，只能在额度允许下一个成功或各预留可分配部分；不能都因为各自读到空闲 100 MB 而成功。

外部工具与旧算法的临时文件也必须受约束。优先通过管道交给受控 writer；必须写目录的 MFA/FFmpeg/原生工具使用能强制总字节上限的作业工作空间（例如经过验证的文件系统项目配额或受限卷），与账户 reservation 联动。只限制单文件大小、定时扫描或生成后再查大小，都不能证明总空间上限。具体机制在服务器原型中验证；缺少可靠限制时不能将该路径标为支持严格配额。只读共享模型不复制成无人计量的私有缓存。

## 4. 满额行为
- 新上传/新生成/新归档被拒绝，返回 quota_exceeded、当前占用、预留、需要空间、可清理建议。
- 已有结果仍可查看、下载、删除；正常登录退出不被满额锁死。
- 用户可不下载直接删除。涉及用户明确删除动作给出文件数量/大小/关联影响，不强制勾选已下载。
- 用户删除进行中，状态 deleting；实际删除完成后才释放占用。失败标 delete_failed，继续占用并提供重试。
- 下载本身不自动删除，不延长寿命，也不当作权限转移。
- 重生成不会覆盖旧批次；需要新预算。不能借重名覆盖逃避保留记录与额度。
- 若批次生成中达到空间上限，默认取消本批并清理未提交临时文件；如保留部分结果，必须显示 incomplete 并计入实际额度，不能伪称全部成功。

## 5. 7 天时限
- 输入资源：上传最终确认时刻 + 7×24 小时。
- 输出资源：任务成功提交结果时刻 + 7×24 小时。
- 下载、浏览、编辑已有文件名或改项目名均不续期；明确新上传/新生成才创建新资源期限。
- 纯复制、改名、重新打 ZIP、刷新下载地址不算新的科研生成；归档截止不得晚于所含资源最早到期时间，不能靠反复打包续存。实际重新计算生成的研究结果按新结果期限计量。
- 未完成上传和失败暂存：建议 24 小时内回收，且不能超过其已有明确 deadline。
- 作业引用输入时校验剩余时限；预计运行会跨输入到期则拒绝/要求重新上传，不隐式保留超过一周。
- 到期立即禁读，含 Range、SSE 返回的产物 URL、缓存和归档。开放链接不永久绕过资源截止。
- 正常运行中提前 60 秒调度待到期项并准备停止引用，在用户可见截止时执行禁读和删除；不能在标示截止前无提示地删掉仍有效结果。按最多 7 天目标验收删除延迟，不把 API 隐藏当成物理删除成功。
- 宕机期间无法承诺物理删除动作按时发生：启动恢复先清理到期数据再开放下载，记录延迟。对外说明区分到期不可访问与异常恢复删除，不作不真实的绝对保证。
- 文件备份、对象版本、CDN 和调试日志不能另存长期音频。未来使用对象存储时，服务端截止与物理生命周期一起验证，不能只依赖可能延迟的供应商自动清理。
- 保留最少审计：账号 ID、时间、字节数、错误码和任务状态。日志不含完整语料、波形数组或敏感绝对路径。

## 6. 暂定数据库对象（仅设计，未迁移）
| 对象 | 关键字段与约束 |
| --- | --- |
| users | id、登录名、password_hash、状态、created_at；登录名唯一 |
| sessions | token_hash、user_id、expires_at、revoked_at；不存明文 token |
| projects | id、owner_id、name、created_at；临时组织，不延长资源 TTL |
| assets | id、owner_id、project_id、kind、storage_key、size、hash、created_at、expires_at、state |
| quota_accounts | user_id 唯一、quota/used/reserved、revision；非负 |
| reservations | id、owner_id、upload/job、bytes、lease、state、idempotency_key |
| jobs | id、owner_id、module/config/input、状态、attempt、lease、deadline、result_manifest |
| job_events | job_id、sequence、stage、progress；不重复序号 |
| deletion_tasks | asset_id、due_at、attempt、result；幂等 |
| audit_events | actor、action、对象 ID、时间、脱敏原因 |

数据模型冻结后，编写有升级/回滚步骤的迁移；不在本轮创建数据库，也不复用旧站表。

## 7. 任务调度与计算并发
10 人可同时操作。起步建议 2 个重型 worker、每人 1 个运行任务，其余排队；这些为压测起点，不是承诺的机器能力。
API 的并发连接不等于计算并发。音频转换/参数批处理/MFA/VTL 的预算不同；避免单个用户抢满全部执行槽。
claim 在短事务内完成，使用 SKIP LOCKED 认领 + lease_generation；执行期间不长时间持有数据库事务。
worker 定时心跳；旧 worker 的结果提交需匹配当前租约代数，避免超时后旧进程覆盖新重试结果。
crash 后任务标 interrupted；只有明确幂等且输入未过期的任务才能安全重试。研究者应能看到重试/失败，不能静默产出两批同名文件。
取消请求先置 cancel_requested，算法检查取消点；外部进程由本 worker 持有并有限时终止。写出完整 manifest 后与取消竞态的优先级在事务中决定。
每批输出独立目录。completed manifest 是完成标记；取消/失败清单保留 incomplete。
原生 VTL 状态按任务或独立会话进程隔离，不共享一个全局 DLL 实例。
实时声道连续发声另作会话能力验证，不占用普通长任务接口假装低时延。

## 8. 必测场景
Q01 同账号多个请求争用最后一段配额；Q02 未知长度上传；Q03 ZIP 展开比巨大；Q04 生成到边界。
Q05 用户直接删且未下载；Q06 下载中到期；Q07 正在使用的输入到期；Q08 worker 崩溃后预留恢复。
Q09 删除失败不释放；Q10 断电留下临时文件；Q11 重复提交同幂等键；Q12 借他人 ID 下载/取消。
Q13 满额仍能登录下载；Q14 导出 ZIP 空间；Q15 服务宕机超过到期后恢复；Q16 磁盘整体水位不足。
Q17 旧 worker 提交被 fencing 拒绝；Q18 多标签页清理与生成竞态；Q19 下载不续期；Q20 输入/结果 TTL 独立。

Q04 还覆盖外部程序同时写多个临时文件与绕过 Python writer 的尝试；Q20 覆盖 ZIP/复制不能给旧资源续期。Q01 验证逐块 used/reserved 转账不重复计量，并注入写入后、结算前崩溃。
