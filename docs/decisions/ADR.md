# 架构决策记录 · D0.3

日期：2026-09-09。以下“采用”是本规划采用，只有明确用户约束属于已确认需求；代码原型尚未验证的技术选择标为暂定。变更决策先追加新条目，说明替代哪一条及迁移代价，不能静默改口。

## ADR-001 一个仓库、独立 v3 工作目录
- 状态：规划采用；本地 worktree 已建立。
- 背景：用户担心前后端分仓影响 EXE 打包，且要保留可用 v2。
- 决策：本地 `PhoneticToolbox_v3` 是同一 Git 仓库的 `codex/v3-rebuild` 工作树；前端、API、桌面宿主、科学核心分目录，不强制分远程仓库。427 个当前源码/资源文件纳入本地源码基线。
- 替代：原目录直接改动容易干扰 v2；完整复制含环境/缓存会制造不可追溯副本；两个远程仓库需要额外协调接口和版本，当前单人项目收益有限。
- 代价：worktree 的 Git 元数据相互关联，不能随意移动/删除共同 Git 目录。后续需要独立仓库时按完整历史或明确导出策略处理。
- 证据：[Git worktree 文档](https://git-scm.com/docs/git-worktree)。本地原目录 hash/HEAD/index 记录见 [基线](../baseline/README.md)。

## ADR-002 一套 Web UI，同时进入桌面宿主和浏览器
- 状态：方向采用，框架方案暂定 Vue 3 + TypeScript + Vite。
- 决策：frontend 输出同一套静态资源；宿主能力接口提供选择目录、设备、下载等差异；全部 15 模块在应用侧栏切换，原有 HTML 页面逐步编入统一路由与主题。
- 替代：继续 Qt Widgets 与网页各做一套，会导致外观与行为再次分叉；全部算法改写 JS 会增加科学回归风险；整站直接复用旧他人仓库不满足用户独立方案要求。
- 代价：既有 React/原生 HTML 要提取逻辑并适配，初期可受控嵌入，但不可无限期保留互不通主题/状态的 iframe 孤岛。
- 约束：现有已许可代码可复用；重写页面外层不等于删除算法来源。Vue 是选型提案，不宣称当前已安装/已实现。

## ADR-003 桌面宿主候选 PyQt6 + Qt WebEngine
- 状态：暂定，P01 原型决定是否冻结。
- 理由：继承 Python、Qt 和本地设备经验；核心/本地服务可同发行包携带，浏览器界面不要求服务器在线。
- 替代：Electron 增加独立 Chromium/Node 宿主与 Python sidecar 的维护；Tauri 增加 Rust/系统 WebView 差异；PySide6 的绑定/许可不同，可能值得选择，但仍需验证兼容性。
- 代价：WebEngine helper、多进程退出、资源目录和单文件解包要真实验证；PyQt 不是可随意标为 LGPL 的依赖。
- 门槛：P01 完成 Windows 单文件启动/退出、音频/IPA/多图、平台原生依赖与许可检查。失败时保留共享 UI/Core 方向，替换宿主并重估包装，不能直接删掉“单文件直用”要求。
- 官方依据：[Qt WebEngine](https://doc.qt.io/qt-6/qtwebengine-overview.html)、[PyQt 许可说明](https://www.riverbankcomputing.com/software/pyqt/intro)。

## ADR-004 科学核心按已有行为搬迁
- 状态：采用。
- 决策：先迁移可用函数和数据模型，输入为数组/显式配置，输出为结构化结果；GUI、全局 settings、用户目录、设备、网络和权限留在适配层。
- 替代：全部重写成本高且改变科研输出；原封不动调用包含 Qt 和全局配置的旧 services 会让多用户互相覆盖。
- 代价：有些“core”实际仍含播放/导入退出，需要拆壳；第一轮迁移与算法优化分开验收。相同函数不能在 API 与 EXE 分别维护两个版本。
- 判断标准：参照 v2 参数/后端/数据生成的独立基线，不能以“不报错”认定等价。

## ADR-005 FastAPI + PostgreSQL 持久任务 + 独立 worker
- 状态：规划采用，性能参数待 P11 实测。
- 决策：API 负责短请求，数据库保存任务/租约/进度/配额，worker 进程执行重计算；初始最多 2 个全局重任务、每账号 1 个，其余排队。10 并发用户是交互和排队能力，不等于 10 个原生计算同时跑。
- 替代：进程内线程/BackgroundTasks 重启即丢，无法承担持久科研任务；直接上 Celery+Redis 增加部署组件，当前规模不必先承担；若 PG 队列被测出瓶颈再通过队列 port 替换。
- 代价：需要自行认真实现 lease/heartbeat/fencing/幂等/取消/恢复，SKIP LOCKED 本身不解决这些问题。
- 官方依据：[FastAPI 重后台计算说明](https://fastapi.tiangolo.com/tutorial/background-tasks/)、[PostgreSQL SKIP LOCKED](https://www.postgresql.org/docs/current/sql-select.html)。

## ADR-006 Web 配额与保留期是服务端强约束
- 状态：5 GB/7 天由用户提出；字节定义和计量细则为本规划明确化。
- 决策：每账号 5,000,000,000 字节，上传/结果/工作临时文件计入，模型共享只读不计；used + reserved 原子约束，超额禁止新增写入，仍允许下载/删除。上传从成功上传起计时，生成物从成功生成起计时，最多 7 天；下载不续期。
- 替代：只查前端或只统计最终 WAV 会被并发与 ZIP/临时文件突破；只用访问时清理会无限滞留无人访问文件；把每次下载当续期违背最长保留。
- 代价：任务需要受控 writer；清理失败仍计量并报警；断电时物理删除无法保证准点，因此必须到期禁读、恢复先清理并记录滞后。
- 精确边界：[账号/存储/任务规格](../specs/accounts-storage-jobs.md)。不执行任何数据库迁移于本轮。

## ADR-007 原生状态、设备与实验时序分开处理
- 状态：采用。
- 决策：VTL 等原生可变状态按任务/专用进程隔离；设备由拥有设备的宿主控制；感知实验在客户端预加载、调度和计时，服务器只管理配置/刺激/结果。
- 替代：把实时按键送服务器计时会掺入网络延迟；共享 VTL 全局状态会串用户；网页无法无条件获得本机文件/设备权限。
- 代价：Web 实时声道控制与高帧率采集有单独验收指标，未通过不能宣称与桌面完全一致。Web 上传不可直接反序列化任意 pickle。

## ADR-008 来源注册表同时驱动软件和说明书
- 状态：用户明确要求，规划采用。
- 决策：记录源码/论文/数据/模型/字体/图标的用途、原作者、版本/commit/hash、修改、许可证证据、仓库/DOI/官方 PDF。区分依赖、移植、方法参考与视觉参考。
- 替代：只在 README 写“感谢”遗漏软件入口；只引论文但不留代码版权不能替代许可义务；来源一概写原创会误导研究者。
- 代价：历史来源有缺口，需要按函数补查。许可证未知的分发材料必须解决后再发布，论文开放访问不等于代码/数据获得同样许可。
- 数据：[source-registry.json](../../third_party/source-registry.json)。本轮是审计基线，尚未实现 UI 来源读取。

## ADR-009 各系统分别构建并验收
- 状态：采用。
- 决策：同一版本源码按 Windows/macOS/Linux 构建；Windows 单文件直用与安装包分别验证；Mac 无实机时标未测；WSL 只验证 Linux 服务端，不能替代 Linux 桌面设备验收。
- 替代：一个 Windows EXE 不能改扩展名变成 Mac 应用；CI 编译成功不等同音频/摄像头实用。
- 代价：增加原生构建矩阵与签名流程，按平台分批发布不虚报全平台通过。
- 官方依据：[PyInstaller 非交叉编译器](https://pyinstaller.org/en/stable/)、[GitHub 托管构建系统](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners)。

## ADR-010 小步迁移与明确退役条件
- 状态：采用。
- 决策：每模块“源码/行为记录 → 核心迁移 → 对照 → 统一页面 → 双端验证 → 来源与说明书”，一个闭环后再推进。legacy 代码有清理阶段但不立即删除。
- 替代：一次整体改写难定位差异；旧前端/API 无依赖就直接删掉，可能损失独有未提交工作。
- 代价：过渡期新旧结构共存；构建只能指向选定的新入口，不隐式引用原 v2 绝对路径。
- 现状：旧 frontend 有未提交修改，旧 API 缺少有效 Git 工作树，尚未满足用户条件性删除要求。

## ADR-011 环境以实测为准
- 状态：采用；用户再次确认开发时使用 phonetic_311。
- 决策：将当前 conda phonetic_311/Python 3.11.14 作为 v2 比较环境，保存安装元数据；v3 独立环境在 P02 建立，先验证版本再锁定。
- 原因：当前 NumPy 2.2.6 / OpenCV 4.13.0.92 与声明的 numpy<2、opencv<4.12 不一致。不能盲目照抄声明或自动修改 v2 环境。
- 代价：必须用固定样例验证环境调整后的数值；版本号列表只是环境事实，不代表整个环境兼容性已经通过。

## ADR-012 P01 Windows 技术基准与隔离构建
- 状态：P01 Windows 原型已验证；完整技术栈与发行策略尚未整体冻结，不扩大授权到 P02 或业务迁移。
- 证据：[P01 报告](../testing/p01-host-probe-report.md)。采用项目内独立 CPython 3.11.14、PyQt6/WebEngine 6.11.0、Qt 6.11.2 作为本地探针基准。conda 派生环境与工具 PATH 分别造成 ICU DLL 冲突，已有导出符号和 Analysis TOC 证据；不修改原环境解决。
- 决策：构建器仅对当前构建进程限定 DLL 搜索路径，并审计每个原生输入；静态页面经只读自定义 scheme 装载，无额外 HTTP 服务。这是 P01 探针边界，正式本地 API/鉴权仍按 ADR-005 与总架构由 P02/P06 实现。
- 输入输出：WAV 原始采样率/声道/整数半开区间保持独立于声卡采样率；选区渲染逐样本对照，播放端数字回环单独验证。
- 选择：保留经过单文件和数字输出验证的 PyQt6 路径。PySide6 实际试验仅完成启动/字体/设备枚举，共用鼠标交互探针未通过；Electron/Tauri 只做官方资料比较，不冒充本机实测。
- 门槛：PyQt 绑定许可、VTL/IRAPT/WM-PC 与历史未授权材料需要形成一致的发行策略；Mac/Linux 原生构建、设备、干净 Windows 环境和 P03 科学等价性尚未通过。上述未决项不能通过把项目统称 MIT 或原型截图来闭合。
