# 首次准备、内容校验复用与退出清理

2026-10-07，井井明确授权。实现及成品验收状态见[计划](../plans/2026-10-07-persistent-startup-cache.md)和[报告](../testing/2026-10-07-persistent-startup-cache-report.md)。限定 Windows 本机功能 verified，首次启动性能回退单列，未将首次速度标为合格。

此前单文件在每次启动恢复临时运行文件，正常退出后回收。新方案使用小型单文件启动器，附带应用、科学组件及主原生组件三个不透明 XZ 段。大段放在启动器 CArchive 前，bootloader 只展开自身的小型 Python 引导文件。应用仍由同一次源快照构建成 onedir，科研进程继续使用这套应用与原独立科学解释器，没有复制业务实现。

缓存位于当前用户数据 `PhoneticToolbox/v3/startup-cache`。三个组件各自以内容清单的 SHA-256 寻址。实际目录使用摘要前 32 个十六进制字符缩短 Windows DLL 路径，完成标记验证完整摘要，碰撞明确失败并保留原文件。版本号不作为身份。每次启动校验清单中全部文件内容，同一硬链接在本次校验中只读取一次，修改日期不能代替内容身份。目录祖先在本次维护锁内检查一次，每个文件单独检查类型及重解析点，不跨次启动保留检查结果。

原生组件仅共享大小和 SHA 相同的字节，硬链接不可用时复制并校验，不使用 junction 绕过路径限制。每次恢复使用独占暂存目录，完成后发布。短暂 Windows rename 占用做有界重试；损坏、中断、权限、空间和路径错误留下诊断。进程文件锁串行准备，租约覆盖启动器、界面及冻结工作进程，活动实例禁止删除。缺失或损坏时修复，其他实例使用中的目录保留。

项目自有 `resources/` 中的四个原生程序文件属于应用组件，Qt 等第三方主组件独立。M10 原生程序库的更新只改变应用身份，不连带使未变化的 Qt 组件失效。每份构建仍保存具体原生文件身份，当前并行工作更新的 M10 文件不能描述为旧版字节完全相同。

安装版安装同一个分发 EXE，同步调用 `--ptb-prepare-cache`，准备失败须报告。卸载调用 `--ptb-clear-all-caches`，存在活动实例或清理失败时要求关闭/重试。普通安装写正常卸载信息，QA 生成真实卸载器但关闭注册及快捷方式。

设置清除全部缓存须确认，并通过现有未保存检查、原生任务检查和录音收尾。取消退出不请求清理。内部处理结果只删登记副本，保留原始输入、唯一唇形采集、设置、草稿、工程和正式导出。浏览器缓存单独定位，不能整删 IndexedDB/localStorage 所在 profile。下载缓存继续保护正在应用的更新及归属不明目录。

首次、修复或补充升级文件时显示原生阶段提示与真实进度，暖启动不重复显示首次提示。未改变的组件跨版本复用。分发包仍是完整离线包；缓存复用减少本机准备工作和重复占用，不等于增量下载。

依据：[PyInstaller 运行目录与入口](https://pyinstaller.org/en/stable/runtime-information.html)。CArchive 偏移/cookie 同本机安装版本 `CArchiveReader` 核对，合并后必须读回及实际执行，不能仅由文件结构推断可用。
