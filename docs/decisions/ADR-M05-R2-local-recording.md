# ADR-M05-R2：实时保存、本地输入与方法身份

日期：2026-10-03。状态：accepted，按井井本轮修复请求实施。验证范围见 [M05-R2 报告](../testing/2026-10-03-m05-r2-report.md)。

## 原因

默认系统输入可能指向立体声混音。旧页面只显示媒体含音轨，无法提示输入电平过低。桌面已经存在 MP4/WAV 保存，但保存后禁用按钮，候选唇形无同名伴随文件，用户容易将重新分析当作保存前置条件。

## 决策

- 自动输入根据授权后可见名称优先选麦克风，排除已知立体声混音/回环名称；未知设备保留系统选择并显示实际音轨。显式选择不替换，精确 ID 失效报错。只改变本次流，不修改操作系统设备配置。
- 电平监测接原始音轨并独立读取，不连接扬声器、不改变录制采样、不增加增益。三秒内峰值一直低于 −60 dBFS 时提示检查输入。导出检查全部解码 PCM 的峰值/RMS。此阈值仅提示低信号，不判定有无人声。
- 停止后直接调用本机录制导出，不提交分析任务。MP4、WAV、完整候选记录及可用的同名唇形交换文件一并保存。另存继续可用，取消和失败保留内存录制。
- `ptb.lip/1` 元数据增加可选、有界的字符串 `source_backend`、`source_status`，原数值字段及时间语义不变。实时文件标为 candidate，方法身份随读取/再保存保留。只有至少两帧有效唇开数据且符合既有预算才生成自动关联文件，检测不足时保留媒体和完整记录并提示。
- legacy FaceMesh 重新分析保留为用户可选流程。V2 与 Web Face Landmarker 的模型差异不因文件格式互通而消失。本轮不实现原生实时 legacy 后端，不提高浏览器方法的等价等级。
- 独立网格按当前结果预览帧的共同包围盒放大到画面宽/高的 82% 内。整段共享变换，相机叠加仍用原始像素坐标。测量、原始坐标及动画文件导出算法不变。

## 平台范围

优先 Windows 本地宿主。浏览器独立保存的现有能力边界继续保留。网页轻后端的可能性见 [计算分工说明](../specs/2026-10-03-client-compute-assessment.md)，该说明未授权或实施其他模块迁移。
