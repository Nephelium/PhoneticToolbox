# 开发源码统一绑定与发行快照

2026-10-07，按井井已确认的源码统一方案实施。

## 决定

项目自有代码只在工程源码目录维护。开发启动器在导入项目包之前绑定本工程的科学核心、后台和桌面源码，并把相同绑定交给其子进程。独立 EGG/LPC 与唇形解释器仍保留原库构建，以固定入口读取同一项目源码。发现已导入其他位置的同名项目包时明确失败，避免混合两个版本。

主工作台使用现有 m14 环境。它已包含当前主环境的科学和 Qt 依赖，并有 M14 所需 python-docx/xlrd；切换前核对原生文件身份。模块 PowerShell 入口仅转发模块 ID 和公开参数，原有脚本名称保留。

前端仍从 frontend/src 生成 frontend/dist。原生 DLL/WASM 等由对应源码构建，开发入口统一不代替这些构建步骤。已安装旧核心副本和历史环境暂时保留，不再作为正常源码启动的回退来源。

发行构建先冻结项目代码，再从这一快照分析依赖和收集模块。打包产生的复制文件不作为独立维护分支。对应源码清单记录当前未提交源码的逐文件 SHA，不能仅用 Git commit 表示实际构建输入。

## 不合并的边界

进程隔离、第三方库版本和数据协议维持各自职责。同名而内容不同的库不得因缩包混用。完全相同的只读依赖可在单独验证后共享；本轮体积审计不代表共享展开机制已经实现。
