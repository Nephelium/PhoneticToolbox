# ADR-P17-M08：即时原音显示与有界预览写入

- 日期：2026-10-01
- 状态：accepted，P17 用户授权内，Windows 本机范围
- 范围：M08 加载与鼠标编辑，不改 Praat 分析、合成算法、采样率或音频量化

## 问题与证据

0779bee 页面等待持久 F0 预览任务完成后才显示波形。真实 0.532 秒录音冷/热波形约 2.30 秒，真实 34.499 秒录音达到 106.388 秒。旧管道每次 ReadFile 最多 4096 字节，M08 Receiver 收到片段立即调用受控文件 write，每次伴随 fsync 和本机状态持久化。完整 FLOAT64 预览产生数千次小写入。证据位于忽略目录 output/validation/p17/M08/baseline-2026-10-01T11-01-04-729Z。

## 决定

1. 页面先通过公共 audioPreview 读取原录音，保留原采样率、声道及时间范围，立即开放波形/试听；随后以原输入SHA执行既有F0任务。F0加载状态明确显示，合成需等待完整轨迹。原格式无法由公共预览解码时仍走原科学预览回退。
2. 每次选择拥有独立AbortController与generation；读取、解码、F0、历史、结果显示均验证归属。F0完成不得重置用户已经平移/缩放的原音视窗。
3. 本机M08输入与临时写入沿用既有1MiB上限。M08 Receiver把管道片段聚合到至多1MiB后写入，最后不足一块按文件真实长度提交。哈希、fencing、配额、取消、完成帧及64MB输出总预算保持。托管存储继续原写入上限。
4. 修正F0右向左手绘端点颠倒：插值基于有方向的起止索引。此为编辑手势修正，与旧V2同源缺陷存在行为差异；不更改原F0或科学计算公式。

## 验证边界

真实输入冷/热波形和F0完成分别计时。对照旧任务输出的metadata/WAV逐字节，并以原V2合成函数核对。聚合边界、截断、错误哈希、额外尾随数据使用非音频任意字节结构测试。实际取消与后续恢复另测。Windows Chrome经真实本机服务的证据与实际Qt证据分开报告，未据此开放Linux或远程计算。

## 最终实测与追加归属修复

旧/新3份自然输入metadata与FLOAT64预览共6产物逐字节一致。原V2三种速度固定Praat随机seed42后26267数组值、3个PCM16导出逐字节一致；随机控制仅用于对照无声重合成，不修改产品默认随机行为。实际取消305ms、后续恢复1085ms；10项聚合/损坏流结构检查通过。

最终长音冷/热：首显211/212ms，解码worker24.30/20.00ms，F0+历史3898/3581ms，原音read桥33.29/24.42ms。证据browser-2026-10-01T11-52-18-335Z。页面首显和F0完成分别报告，不称全计算即时。

真实本轮输出重命名与删除验收发现删除后旧结果读取可能报410，页面以已删除ID集合、resultEpoch守卫过滤迟到读取，同时清空已删除当前结果/播放状态；11-49-52删除后1800ms无410及原输入SHA不变通过。
