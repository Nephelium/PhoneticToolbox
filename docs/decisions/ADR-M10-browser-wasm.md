# ADR：VTL 浏览器执行复用原生源码和 Python 状态机

日期：2026-10-18。状态：已完成本地实现与Chrome验证。授权：井井要求尝试 WebAssembly，在用户浏览器运行并保持算法/功能、验证结果和性能。

## 选择

优先使用工程既有 Pyodide 执行共用 Python 状态机，以锁定 Emscripten 将 VTL 2.4 C++ 及既有 m10/r18 补丁编译为 Wasm 动态库，通过现有 ctypes 接口调用。一个独立 Worker 拥有该声道会话、合成/分析/几何状态和全部计算输入，退出销毁。浏览器文件选择、下载、播放和主题继续使用现有平台能力。

## 其他路线

- 独立 Wasm 模块加 JS 绑定：原生 ABI 更独立，但需要显式内存搬运和替换 Engine 原生库端口；作为动态库/状态隔离不可行时的备选。
- 全部改写为 JS：重写几何、声学求解和状态机风险较大，无法仅凭功能相似证明保留科研语义，本轮不采用。

## 保持与验证

不修改 VTL 声学公式、采样时钟、源模型、舌形补丁或输出文档。不同编译器的浮点和随机序列差异分别量化，原生精确回归保持。装载与三份可变状态隔离是第一道门槛；之后验证所有科学结果、用户操作、故障/取消、冷/热性能和实际浏览器。

服务器回退只在会话建立前选择，避免途中静默丢失状态。服务器额度、账号权限和内容期限保持。视频容器编码与科学合成分开记证据。工具链/大型运行库按需下载并锁定摘要，不进入桌面资源树。本轮不扩大公开部署授权。

实际装载已证明ctypes侧模块路线可行，无需替换Engine的调用层。最终功能/科学/性能及实际资源缺失回退见[验收](../testing/m10-wasm-report.md)。井井明确接受0.001dB及同量级小浮点差异；原始严格检查和正式随机抖动的跨平台轨迹差异仍保留记录。
