# ADR-M01-R4：30分钟有界分析与 EGG 联合参数

2026-10-04，井井批准实施，并将最长输入从1小时调整为30分钟。状态：accepted，Windows开发态的实现与验证范围见[报告](../testing/2026-10-04-m01-r4-report.md)。

## 问题与决定

旧参数估计把完整多声道音频及全部结果装入内存，并受200万采样值、240秒计算预算约束。单纯放宽该上限无法控制一小时录音的内存、序列化和前端绘图成本。新本机工作台使用显式 `extended.revision=bounded/1`，准入上限固定1800秒。恰好1800秒接受，多一个采样点拒绝，桌面导入前与计算前均核查。

音频和EGG声道由用户指定，双声道可以为单个文件交换。试听选择与分析角色分离。默认EGG关闭，音频维持全部声道混合；开启EGG后默认音频2、EGG1。单声道文件只计算声学参数，并在界面与结果元数据记录跳过EGG。

左侧分析设置下增加内嵌EGG选项，复用“开始全列表分析”、批次记录和两格式保存。右栏常驻单文件进度区，与批次完成数分开，完成、失败、中断均保留其位置和最后状态。

## 科学计算与可追溯性

- 新计算修订 `acoustic-bounded/1`，EGG修订 `egg-bounded/1`。无扩展字段的旧请求继续原路径，旧配置序列化省略该字段，保留旧幂等哈希和 `acoustic/1`、`acoustic/2` 结果。
- 20秒为一个输出块，两边读取上下文，默认至少1秒，并随分析窗、周期数、能量窗、声学/唇形平滑窗增大。全局整数帧序号决定归属，仅裁剪每块负责的帧，避免重复帧或逐块拼接导致的时间漂移。
- 预扫描取得整份录音的通道峰值、线性趋势和最大强度。新修订统一使用全局静音参考，包括“仅有声帧”开启的情况，防止低振幅块独立归一化后重新出现基频。旧请求的掩码语义保持原样。
- 科学计算始终使用原始音频，按声道分离后计算。按参数选择跳过无关重计算阶段；共振峰、基频等依赖仍按既有实现取得。原生REAPER依照每个带上下文的块执行。
- Praat/REAPER路径优化及滤波端点存在上下文依赖。重叠裁剪降低边界影响，**不宣称新分段结果与V2整段调用逐位相同**。元数据记录 `pitch_policy=per-block-path/1` 与 `context_policy=overlap-crop/1`。
- EGG使用全局峰值0.7归一化与全局去趋势，复用M03滤波、GCI/GOI检测、CQ/SQ及GCI F0方法。事件按全局采样边界分配，保留比例阈值法的亚采样点精度，随后在全局事件序列上构建周期，跨块周期只计算一次。
- CQ为接触时长/周期时长，严格接受0.05<CQ<0.95。SQ沿用旧实现 `(去接触时长−接触建立时长)/接触时长`，不能解释为常见的两阶段时长比。CQ/SQ位于周期起点，GCI F0位于两次GCI的中点。GCI F0沿用全局MAD过滤及低于100Hz的保留规则。
- EGG静音掩码沿用M03批量的全局归一化音频20ms平均绝对振幅，分别在CQ/SQ起点和F0中点采样。与声学强度阈值分开记录。
- 插值模式将CQ、SQ、GCI F0线性插值到主参数帧，可选保留缺口的平滑，默认20ms，0关闭。默认最大插值间隔50ms，禁止跨无效周期、长缺口及外推。两种模式均保存原始周期结果。
- 可选GCI F0派生分支使用音频声道及插值后的GCI F0作为输入，添加明确的 `(gF0)` 谐波、修正谱倾斜、CPP、HNR、SHR和Slope列。派生输出使用声学平滑设置；EGG显示列使用独立平滑设置。Praat/REAPER列保留，Jitter/Shimmer维持原定义，不冒充GCI周期扰动指标。
- 来源沿用既有M01来源登记及 `PENDING-EGG`。该标记仍表示原始文献对应和完整授权链未解决，本轮没有补造引用或授权。

## 文件格式与显示

新文件标记 `m01-bundle/2`，每个XLSX/SQLite都含 `params`、可选 `egg_cycles` 以及 `ptb_metadata`。周期表包含CQ/SQ/gF0及GCI、下一GCI、GOI、F0中点时间。插值模式的主表增加三列，周期模式的主表维持原网格。超过100万数据行时XLSX自动分续表，不超过Excel单表行上限。

SQLite逐块写盘，XLSX采用write-only导出。非有限值：NaN为空单元格/NULL，无穷值为显式 `+Infinity`/`-Infinity` 文本。标注以文字单元格写入，前导等号不会变成公式。元数据包含输入SHA256、配置及其摘要、实际后端、修订和时间策略。内部JSON改为来源/产物摘要，不再复制全部数值。未改写历史结果，也未迁移现存任务库。

M02对新结果按选中列和可见时间窗查询。SQLite直接读取；XLSX首次在受控进程中流式建立SQLite索引，按源哈希复用。前端每像素保留首尾、极值及缺口代表点，坐标轴统计来自窗口完整有效数据。绘图抽样不修改保存表，细节通过缩放重新读取。曲线读取完成前禁止导图，迟到响应丢弃，请求合并且不会因响应更新再次自触发。

默认同源TextGrid切分从已提交结果中解析配套SQLite，核验原音频哈希、采样率和声道，逐块切音频并截取主表/周期表。时间减去实际首样本偏移，另存 `Source_Time_s`，不重新估计。按周期起点决定其所属片段，跨片段边界周期保留原值和原终点，终点可超出片段时长。指定历史参数表入口仍沿用旧格式白名单，新多表结果通过默认同源入口切分。

## 资源与平台边界

新本机音频输入最多2GB、1800秒、8–192kHz、1–8声道；现有波形预览仍有8–96kHz与轻量预览预算。当前声道界面配置双声道1/2；默认混合保留多声道行为。输出每表最多200万行、合计1.8亿单元格，每个参数文件最多4GB，整组最多5GB，临时产物约6GB上限。默认5ms、30分钟为36万主表帧，极小帧移仍可能触发帧数/产物预算。

Windows计算子进程树2GiB预算、最长6小时，单次参数读取进程1GiB/300秒。输入、产物分块传输并核验哈希，任务心跳/取消/进程组清理由原本机任务体系管理。短随机临时路径避免原生REAPER的深目录路径问题。已完成文件才对外提交，取消/失败不发布半成品。

新能力未准入Linux正式任务或远程服务，WSL仅验证纯科学核心。旧远程请求和预算不变。不存在新增全局依赖、现存数据库DDL或数据迁移、V2修改、EXE打包、push或公开发布。
