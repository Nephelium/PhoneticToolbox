# 平台构建与部署边界

本页维护平台差异，Windows 具体流程唯一见[严格打包规则](../../release/PACKAGING_RULES.md)。状态查询台账及对应环境报告，不使用旧原型阶段作为当前完成结论。

| 平台 | 交付与独立验证 |
| --- | --- |
| Windows | 同一应用的单文件 EXE、安装 EXE 与更新 ZIP；验证工程外运行、依赖身份、启动、设备、安装和数据保留。 |
| macOS | 对应 CPU 的 .app/分发包；核对 dylib、Qt helper、权限、签名/公证与实际声音/摄像头/窗口行为。 |
| Linux 桌面 | 对应发行版与原生依赖；核对 glibc、图形栈、音频服务、字体、沙箱及文件对话框。 |
| 服务端 | 静态前端、API/worker、数据库与私有存储；验证 HTTPS、账号隔离、额度/到期、恢复及回滚。 |
| 可信节点 | 版本化 binding、资源硬限制和模块准入；本机状态机模拟不能证明服务端事务或实际科学任务。 |

每个产物记录 app/core/api/assets 身份、平台、构建输入、依赖及来源；实际构建与实体运行证据分开。Windows DLL 或整套 Windows 环境不能直接充当 Linux/macOS 实现，WSL 服务测试不能代替桌面设备测试。

## 环境与服务

- 开发和构建使用已锁定的项目环境，详见[源码入口](../development/source-entry.md)。不照旧 requirements 降级 v2，不修改 NInfer、docker-desktop 或用户其他 WSL 配置。
- Linux 服务使用专用目录、端口和配置，默认本机访问；安装系统工具、创建发行版和现存库迁移按明确授权执行。
- 小服务器先测实际资源，未准入科学能力保持关闭。初始单计算槽和总预算按 P11 证据冻结，不能把套餐参数当性能保证；重任务交由通过准入的可信节点。
- 1 GB/3 天政策、全站磁盘保护、节点缓存及恢复不能相互绕过。账号与最少审计元数据的恢复与语料保留分开。
- API 内部监听、同源 HTTPS、私有文件不直接静态暴露。具体排空、升级与回滚见[运维手册](p15-staging-runbook.md)，论文栏目另见[内容发布](paper-reading.md)。

本地构建不等于公开分发。DNS、系统配置、凭据、数据库、上传和生产发布遵守当前任务授权；旧上传记录不构成新的部署指令。
