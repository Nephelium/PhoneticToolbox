# 仓库内容与本机文件管理

GitHub 保存维护代码、可公开的必要资源和技术文档。工作目录中的全部文件不等于待上传内容，`.gitignore` 也不会自动停止跟踪已有文件。

| 内容 | 本机安排 | Git |
| --- | --- | --- |
| 工程源码、锁文件、契约、构建/测试脚本 | 只维护当前源码 | 保留 |
| 必要原生组件、对应源码包、字体许可、公开最小基准 | 按来源与资源清单维护 | 经核实后保留，不按 exe/zip 后缀误删 |
| `.venv/`、node_modules/、缓存 | 必要环境可复用 | 忽略 |
| dist/、output/、安装包和构建中间物 | 成功换版后清旧包，测试副本用后清 | 忽略 |
| 用户语料、数据库、凭据、私有审计、下载的论文全文 | 保留在明确的本机位置 | 忽略；已跟踪项需单独停止跟踪 |
| manual/.studio/ | 自动恢复稿保留最后一份，成功保存后清历史/已提交事务，失败证据列回执 | 忽略 |
| software-only 素材、生成阅读副本 | 正式素材保留，生成资源随构建替换 | 忽略；不把受限媒体随源码上传 |
| 当前规则、架构、必要验收与来源证据 | 简短入口，详细资料按需阅读 | 保留可公开内容 |
| 整理前文本快照、临时截图与重复副本 | 本机追溯材料或用后清理 | 忽略，不逐次堆备份 |

## 提交前检查

在本项目根目录核对 `git rev-parse --show-toplevel --git-common-dir`、`git status --short`、本次候选文件和 `git diff --cached --stat` / `git diff --cached --name-status`。采用明确文件清单，避免对大量未审阅变动直接 `git add .`。

用 `git check-ignore -v -- <路径>` 检查未跟踪文件，用 `git ls-files -- <路径>` 检查是否已进入索引。忽略规则不替代审阅，也不能阻止显式 `git add -f`。受限素材还需核对 manual/project.json 中 distribution/git 标记。

下载论文目录 papers/ 不属于应用分发源；M18 使用自己的内容分发流程。保留本机 PDF、停止 Git 跟踪不等于删除远端历史。历史改写和公开发布另按授权处理，不为清理工作区擅自执行。

## 保持体积可控

源码改动和必要文档本身很小，主要占用来自依赖、构建展开、编辑素材和验证数据。按[根清理规则](../../AGENTS.md)保留必要环境、最新成品和当前构建依赖，清理可再生测试副本；正式说明书及原始研究数据不套用临时目录策略。

`output/validation/p06/local-state.sqlite3` 和 `m01/workbench-local.json` 指向的缓存仍由源码启动器读取，部分运行时暂存也参与打包。清理前先按[架构数据表](../../ARCHITECTURE.md)核对真实引用。

新增可生成目录时同步添加忽略规则和结束清理方式，执行[产物生命周期](artifact-lifecycle.md)。不要为防止上传而删除运行所需文件，也不要把所有验证目录或所有二进制一概当垃圾。
